Func, Action, and Predicate

Module 2.2 — Advanced Language Features

You already learned:

Delegates
Events
Lambda expressions

Now we move to the three most commonly used built-in delegate types:

Action
Func
Predicate

These are important because in modern C#, you usually do not need to declare your own delegate type for common cases.

1. Why Action, Func, and Predicate Exist

Previously, you could define your own delegate:

delegate int Operation(int a, int b);

Then:

Operation add = (a, b) => a + b;

This works perfectly.

But imagine creating custom delegates for everything:

delegate void Print(string message);

delegate int Calculate(int a, int b);

delegate bool Check(int number);

delegate string Format(string text);

This becomes unnecessary boilerplate.

C# already provides generic delegate types:

Action    → returns void
Func      → returns a value
Predicate → returns bool

So instead:

Action<string> print =
    message => Console.WriteLine(message);

Func<int, int, int> add =
    (a, b) => a + b;

Predicate<int> isEven =
    number => number % 2 == 0;
2. Action
Definition

Action represents a delegate that:

Accepts zero or more parameters and returns void.

Basic form:

Action action;

This means:

parameters → none
return     → void

Example:

Action greet = () =>
{
    Console.WriteLine("Hello");
};

Invoke:

greet();

Output:

Hello
3. Action With One Parameter

Use:

Action<string>

Example:

Action<string> print =
    message => Console.WriteLine(message);

Call:

print("Hello C#");

Output:

Hello C#

The type means:

Action<string>

string → parameter
void   → return
4. Action With Multiple Parameters

Example:

Action<string, int> repeat =
    (message, count) =>
    {
        for (int i = 0; i < count; i++)
        {
            Console.WriteLine(message);
        }
    };

Usage:

repeat("Hello", 3);

Output:

Hello
Hello
Hello

Here:

Action<string, int>
        ↓       ↓
    parameter parameters
        ↓       ↓
     string    int

There is no return value.

5. Action Type Pattern

The general pattern is:

Action
Action<T1>
Action<T1, T2>
Action<T1, T2, T3>
...

For example:

Action<int>

means:

int parameter
void return
Action<int, string>

means:

int parameter
string parameter
void return
Action<int, string, bool>

means:

int parameter
string parameter
bool parameter
void return

Action supports up to 16 input parameters.

6. The Most Important Rule for Action

If the operation does something but doesn't return a value:

Use Action

Examples:

Action save =
    () => Console.WriteLine("Saved");

Action<string> log =
    message => Console.WriteLine(message);

Action<int> printNumber =
    number => Console.WriteLine(number);

Mental shortcut:

Action
   ↓
"Do something."
7. Func

Now consider a method that returns something.

Example:

Func<int, int> square =
    number => number * number;

Func represents a delegate that:

Accepts zero or more parameters and returns a value.

The most important rule:

The last generic type parameter of Func is always the return type.

8. Understanding Func<int, int>

Consider:

Func<int, int>

There are two ints.

The first:

int → parameter

The second:

int → return

So:

Func<int, int> square =
    number => number * number;

means:

int → int
9. Func<int, int, int>

Consider:

Func<int, int, int>

The first two are parameters:

int → parameter
int → parameter

The last is the return:

int → return

Therefore:

Func<int, int, int> add =
    (a, b) => a + b;

means:

(a, b) → result

More specifically:

int, int → int
10. Func<string, int>

Example:

Func<string, int> getLength =
    text => text.Length;

Read it from left to right:

string → input
int    → output

So:

getLength("Hello")

returns:

5
11. Func With No Parameters

You can also have:

Func<int> getNumber =
    () => 100;

There are no input parameters.

The only type argument:

int

is therefore the return type.

Func<int>

parameters → none
return     → int

Example:

Console.WriteLine(getNumber());

Output:

100
12. Func Type Pattern

General structure:

Func<T1, TResult>
Func<T1, T2, TResult>
Func<T1, T2, T3, TResult>
...

For example:

Func<int, bool>

means:

int  → input
bool → return
Func<string, int, bool>

means:

string → input
int    → input
bool   → return
Func<int, int, decimal>

means:

int     → input
int     → input
decimal → return
13. Func Supports Up to 16 Input Parameters

The maximum structure is effectively:

16 input parameters + 1 return type

So:

Func<T1, T2, ..., T16, TResult>

is possible.

In normal code, needing that many parameters is often a sign that the design could be simplified, but the delegate type itself supports it.

14. The Most Important Rule for Func

When you see:

Func<A, B, C>

don't read it as:

A, B, C → all parameters

Instead:

A → parameter
B → parameter
C → RETURN

This rule prevents one of the most common Func mistakes.

15. Predicate<T>

Now we have a specialized delegate:

Predicate<T>

A predicate represents:

A method that takes one value and returns bool.

Example:

Predicate<int> isEven =
    number => number % 2 == 0;

Usage:

bool result = isEven(10);

Console.WriteLine(result);

Output:

True
16. Why Is It Called a Predicate?

A predicate answers a question.

For example:

Is this number even?
Is this person an adult?
Is this product available?
Does this string start with "A"?

The answer is:

true

or:

false

So:

Predicate<int> isEven =
    number => number % 2 == 0;

means:

"Given an integer, tell me whether it is even."

17. Predicate Examples
Check positive number
Predicate<int> isPositive =
    number => number > 0;
Check adult
Predicate<int> isAdult =
    age => age >= 18;
Check long string
Predicate<string> isLong =
    text => text.Length > 10;
Check empty string
Predicate<string> isEmpty =
    text => string.IsNullOrEmpty(text);
18. Action vs Func vs Predicate

This is the most important comparison.

Type	Input	Return
Action	0+	void
Func	0+	Any value
Predicate<T>	Exactly 1	bool

Examples:

Action<string> print =
    text => Console.WriteLine(text);
Func<int, int> square =
    x => x * x;
Predicate<int> isEven =
    x => x % 2 == 0;

Mental model:

Action
  ↓
DO

Func
  ↓
CALCULATE

Predicate
  ↓
CHECK
19. Predicate<T> vs Func<T, bool>

This is an important question.

These two represent essentially the same shape:

Predicate<int>

and:

Func<int, bool>

Both represent:

int → bool

For example:

Predicate<int> isEven =
    x => x % 2 == 0;

and:

Func<int, bool> isEven =
    x => x % 2 == 0;

Both can represent the same kind of behavior.

So why have Predicate<T>?

Because it communicates intent.

Predicate<int>

immediately suggests:

"This is a condition/check."

Whereas:

Func<int, bool>

means more generally:

"This is a function that takes an int and returns bool."

20. Action vs Func

Suppose:

Action<int> print =
    x => Console.WriteLine(x);

It performs an operation:

int
 ↓
void

Now:

Func<int, int> doubleValue =
    x => x * 2;

It calculates something:

int
 ↓
int

If you need the result:

int result = doubleValue(10);

You cannot do the same with Action because it returns void.

21. Func With Different Return Types

The return type doesn't have to be int.

Func<int, string> convert =
    number => number.ToString();
Func<string, bool> check =
    text => text.Length > 5;
Func<double, decimal> convert =
    value => (decimal)value;
Func<int, bool> isEven =
    number => number % 2 == 0;
22. Action Doesn't Return a Value

This is invalid:

Action<int> doubleNumber =
    x => x * 2;

Why?

Because:

Action<int>
    ↓
takes int
returns void

But:

x => x * 2

returns an int.

Use:

Func<int, int> doubleNumber =
    x => x * 2;

Or, if you don't need the result:

Action<int> printDouble =
    x => Console.WriteLine(x * 2);
23. Action With Statement Lambdas

Action is very useful when the lambda contains multiple statements.

Action<int> process = number =>
{
    Console.WriteLine($"Processing {number}");

    int result = number * 2;

    Console.WriteLine($"Result: {result}");
};

Call:

process(10);

Output:

Processing 10
Result: 20

No return is needed because the delegate returns void.

24. Func With Statement Lambdas

For Func, a statement lambda must return a compatible value.

Func<int, int> process = number =>
{
    int result = number * 2;

    return result;
};

The return is required.

This difference is important:

Action
  ↓
no return value

Func
  ↓
must produce return value
25. Passing Action to a Method

Consider:

static void Execute(Action action)
{
    Console.WriteLine("Before");

    action();

    Console.WriteLine("After");
}

Now:

Execute(() =>
{
    Console.WriteLine("Inside");
});

Output:

Before
Inside
After

The method accepts behavior from the caller.

26. Passing Func to a Method

Example:

static int Execute(
    int value,
    Func<int, int> operation)
{
    return operation(value);
}

Usage:

int result = Execute(
    10,
    x => x * 5);

Result:

50

The method doesn't know whether the caller supplied:

x => x * 5

or:

x => x + 100

or:

x => x * x

It only knows the contract:

int → int
27. Passing Predicate to a Method

Example:

static bool Check(
    int value,
    Predicate<int> condition)
{
    return condition(value);
}

Usage:

bool result = Check(
    10,
    x => x > 5);

Result:

true

The method doesn't care about the actual condition.

It only knows:

int → bool
28. List<T> and Predicate<T>

You already learned List<T>.

One of its useful methods is:

Find()

Example:

List<int> numbers =
    new List<int> { 5, 10, 15, 20 };

Find the first number greater than 12:

int result =
    numbers.Find(x => x > 12);

The lambda:

x => x > 12

acts as the condition.

Conceptually:

Find()
  ↓
checks each element
  ↓
predicate(element)
  ↓
true?

This is a direct example of delegates + lambdas being used in the .NET library.

29. List<T>.FindAll

You can also find all matching elements:

List<int> numbers =
    new List<int>
    {
        5, 10, 15, 20, 25
    };

List<int> result =
    numbers.FindAll(x => x > 10);

Result:

15
20
25

The lambda:

x => x > 10

defines the condition.

30. List<T>.ForEach and Action<T>

You can use:

numbers.ForEach(
    x => Console.WriteLine(x));

ForEach expects an action-like delegate.

The lambda:

x => Console.WriteLine(x)

returns void.

So conceptually:

ForEach
   ↓
Action<T>
   ↓
"Do something with each item."
31. Choosing the Correct One

When designing a method, ask:

Question 1

Does the supplied behavior return nothing?

Use:

Action
Question 2

Does the supplied behavior return some value?

Use:

Func
Question 3

Is the behavior specifically a yes/no condition?

Use:

Predicate<T>

Example:

Send email
    ↓
Action

Calculate price
    ↓
Func

Is product available?
    ↓

32. Real-World Example

Suppose we have:

class Product
{
    public string Name { get; set; }
    public decimal Price { get; set; }
}
Action

Print a product:

Action<Product> print =
    product =>
        Console.WriteLine(product.Name);
Func

Calculate discounted price:

Func<Product, decimal> getDiscountedPrice =
    product => product.Price * 0.9m;
Predicate

Check whether product is expensive:

Predicate<Product> isExpensive =
    product => product.Price > 1000;

Now the three types have distinct responsibilities:

Product
   |
   ├── Action<Product>
   │      ↓
   │   DO something
   │
   ├── Func<Product, decimal>
   │      ↓
   │   CALCULATE something
   │
   └── Predicate<Product>
          ↓
       CHECK something
33. Generic Type Parameters vs Parameters

Consider:

Func<int, string, bool>

There are two different concepts here.

The generic arguments:

<int, string, bool>

describe the types.

The actual lambda parameters:

(a, b)

represent the runtime values.

Example:

Func<int, string, bool> check =
    (age, name) => age >= 18 && name.Length > 3;

Here:

age  → int
name → string
return → bool

The actual call:

check(20, "Hari");

provides the runtime values.

34. Func and Action Are Delegates

This is important:

Action
Func
Predicate

are not some completely different mechanism.

They are generic delegate types provided by .NET.

Conceptually:

Delegate
   |
   ├── custom delegate
   |
   ├── Action
   |
   ├── Func
   |
   └── Predicate

So everything you learned about delegates still applies:

method compatibility
invocation
passing as parameters
storing methods
lambdas
multicast behavior where applicable
35. A Subtle Point — Variance

Func and Action support generic variance.

This is an advanced feature and becomes important when delegate types involve inheritance relationships.

For example, Action<T> is contravariant in T, while Func<..., TResult> has variance rules for its type parameters.

The important practical idea is:

Generic delegate types can sometimes accept methods whose parameter/return types are compatible through inheritance relationships, not only exact textual type matches.

You do not need to memorize the variance syntax yet.

It becomes much clearer when generic variance is studied alongside advanced generics.

36. Multicast Behavior

Action and other delegate types can participate in multicast invocation.

Example:

Action notify =
    () => Console.WriteLine("First");

notify += () =>
    Console.WriteLine("Second");

notify();

Output:

First
Second

However, remember the event lesson:

An event is the safer abstraction when the purpose is controlled subscription/notification.

Don't expose a public delegate just because it can multicast.

37. Func Return Value With Multiple Methods

Because delegates can be multicast, this is technically possible:

Func<int> getValue =
    () => 10;

getValue += () => 20;

Calling:

int result = getValue();

does not produce a collection of results.

For multicast delegates with return values, the invocation result corresponds to the last invoked delegate.

Therefore, multicast delegates are generally much more natural with Action/void behavior.

38. Predicate<T> Is a Specialized Concept

You could replace:

Predicate<int> isPositive =
    x => x > 0;

with:

Func<int, bool> isPositive =
    x => x > 0;

But the first communicates intent more directly:

Predicate<int>
      ↓
This is a condition.

Whereas:

Func<int, bool>
      ↓
This is a function producing bool.

Use the type that communicates the purpose of the API.

39. Common Mistakes
Mistake 1 — Treating Func<int, int> as two parameters

Wrong interpretation:

int
int
↓
two parameters

Correct:

int → parameter
int → return
Mistake 2 — Using Action when a result is required

Wrong:

Action<int> square =
    x => x * x;

Correct:

Func<int, int> square =
    x => x * x;
Mistake 3 — Forgetting return in a statement Func

Wrong:

Func<int, int> square = x =>
{
    x * x;
};

Correct:

Func<int, int> square = x =>
{
    return x * x;
};
Mistake 4 — Thinking Predicate accepts multiple parameters

Predicate<T> accepts exactly one input:

Predicate<int>

For multiple inputs, use Func:

Func<int, int, bool>

41. Complete Example
using System;
using System.Collections.Generic;

class Program
{
    static void Main()
    {
        List<int> numbers =
            new List<int>
            {
                10, 15, 20, 25, 30
            };

        // Action
        Action<int> print =
            number => Console.WriteLine($"Number: {number}");

        print(10);

        // Func
        Func<int, int> square =
            number => number * number;

        Console.WriteLine(
            $"Square: {square(5)}");

        // Predicate
        Predicate<int> isEven =
            number => number % 2 == 0;

        Console.WriteLine(
            $"Is 10 even? {isEven(10)}");

        // Predicate with List<T>
        int firstEven =
            numbers.Find(number => number % 2 == 0);

        Console.WriteLine(
            $"First even: {firstEven}");

        // Action with List<T>
        numbers.ForEach(
            number => Console.WriteLine(number));
    }
}

You have now learned the progression:

Method
   ↓
Delegate
   ↓
Anonymous Method
   ↓
Lambda
   ↓

numbers.Find(
    number => number % 2 == 0);

The behavior becomes progressively more local and concise.
