Lambda Expressions in C#

Module 2.2 — Advanced Language Features

1. What Is a Lambda Expression?

A lambda expression is a concise way to represent an anonymous function.

The most important connection from the previous lesson is:

Delegate
   ↓
defines the shape of callable behavior

Lambda
   ↓
provides the implementation of that behavior

For example:

Func<int, int> square = x => x * x;

Here:

x => x * x

is the lambda expression.

It means:

"Take x and return x * x."

2. Why Do We Need Lambdas?

Before lambdas, suppose we have:

static int Square(int x)
{
    return x * x;
}

Then:

Func<int, int> square = Square;

This works, but the method is only being used for a small piece of behavior.

A lambda lets us write the behavior directly:

Func<int, int> square = x => x * x;

So instead of:

named method
    ↓
delegate
    ↓
behavior

we can write:

lambda
   ↓
behavior

This becomes extremely useful with:

Func
Action
Predicate
LINQ
events
collections
callbacks
3. Lambda Syntax

The basic syntax is:

(parameters) => expression

Example:

x => x * 2

There are two main parts:

x       =>       x * 2
│                 │
│                 └── body
│
└── parameter

The => symbol is called the lambda operator.

Read:

x => x * 2

as:

"Given x, produce x * 2."

4. A Lambda Is Not Automatically a Delegate

This is an important point.

This:

x => x * 2

does not have a standalone delegate type by itself.

The compiler needs a target type to understand what the lambda represents.

For example:

Func<int, int> operation = x => x * 2;

Here the target type is:

Func<int, int>

Therefore the compiler knows:

parameter → int
return    → int

So the lambda is compatible.

5. Lambda + Delegate

You can use a custom delegate:

delegate int Operation(int x, int y);

Then:

Operation add = (x, y) => x + y;

Now:

int result = add(10, 20);

Output:

30

Conceptually:

Operation
    ↓
(int, int) → int
    ↓
(x, y) => x + y

The lambda provides the implementation required by the delegate.

6. Lambda With One Parameter

You can write:

Func<int, int> doubleValue = x => x * 2;

Usage:

Console.WriteLine(doubleValue(5));

Output:

10

The parameter type does not need to be written because the compiler gets it from Func<int, int>.

7. Explicit Parameter Type

You can explicitly specify the parameter type:

Func<int, int> doubleValue = (int x) => x * 2;

This is valid.

But usually:

Func<int, int> doubleValue = x => x * 2;

is preferred because the compiler already knows x is an int.

8. Multiple Parameters

For multiple parameters, use parentheses:

Func<int, int, int> add =
    (a, b) => a + b;

Usage:

int result = add(10, 20);

Result:

30

Syntax:

(a, b) => a + b

means:

parameters → a, b
return     → a + b
9. Zero Parameters

A lambda can have no parameters:

Action action = () => Console.WriteLine("Hello");

Notice:

()

represents zero parameters.

Usage:

action();

Output:

Hello
10. Lambda With a Return Value

Example:

Func<int, int> square =
    x => x * x;

The expression:

x * x

is automatically returned.

So:

x => x * x

is approximately equivalent to:

static int Square(int x)
{
    return x * x;
}

The important difference is syntax and how the function is being supplied.

11. Expression Lambda

A lambda with a single expression is called an expression lambda.

Example:

x => x * x

Another:

(a, b) => a + b

Another:

name => name.Length

The expression's result becomes the return value.

Example:

Func<string, int> getLength =
    text => text.Length;

Then:

Console.WriteLine(getLength("Hello"));

Output:

5
12. Statement Lambda

A lambda can also contain multiple statements.

Syntax:

(parameters) =>
{
    statement1;
    statement2;
    return result;
}

Example:

Func<int, int> calculate = x =>
{
    int doubled = x * 2;
    int result = doubled + 10;

    return result;
};

Usage:

Console.WriteLine(calculate(5));

Output:

20

Because:

5 × 2 = 10
10 + 10 = 20
13. Expression Lambda vs Statement Lambda
Expression lambda
Func<int, int> square =
    x => x * x;
Statement lambda
Func<int, int> square = x =>
{
    int result = x * x;
    return result;
};

Mental model:

Simple logic
    ↓
expression lambda

Multiple statements / control flow
    ↓
statement lambda
14. return Rules

For an expression lambda:

x => x * 2

you don't write:

x => return x * 2; // invalid

The expression is implicitly returned.

For a statement lambda:

x =>
{
    return x * 2;
}

you explicitly use return.

15. Lambda Parameter Types

Suppose:

Func<int, int> operation =
    x => x * 2;

The compiler knows:

x = int
return = int

because of:

Func<int, int>

Now:

Func<string, int> operation =
    text => text.Length;

The compiler knows:

text = string
return = int

This is called type inference in this context.

16. Parentheses Around Parameters

For one parameter, you can usually omit parentheses:

x => x * 2

You can also write:

(x) => x * 2

Both are valid.

For multiple parameters:

(a, b) => a + b

Parentheses are required.

For zero parameters:

() => Console.WriteLine("Hello")

Parentheses are required.

17. Lambda Passed Directly to a Method

You don't always need to store a lambda in a variable.

Suppose:

static void Execute(Func<int, int> operation)
{
    Console.WriteLine(operation(10));
}

You can directly pass:

Execute(x => x * 2);

Output:

20

The lambda is passed directly as behavior.

This is one of the most important patterns in modern C#.

18. Lambda as a Callback

Remember callbacks from delegates.

Instead of:

static void Process(
    Func<int, int> callback)
{
    int result = callback(10);

    Console.WriteLine(result);
}

You can call:

Process(x => x * 5);

The caller provides the behavior:

Process()
   ↑
   |
x => x * 5

This makes APIs highly flexible.

19. Lambda and Action

Action represents a delegate that returns void.

Example:

Action greet =
    () => Console.WriteLine("Hello");

Usage:

greet();

With a parameter:

Action<string> print =
    message => Console.WriteLine(message);

Usage:

print("Hello C#");

Multiple parameters:

Action<string, int> repeat =
    (message, count) =>
    {
        for (int i = 0; i < count; i++)
        {
            Console.WriteLine(message);
        }
    };
20. Lambda and Func

Func represents a delegate that returns a value.

Example:

Func<int, int> square =
    x => x * x;

Another:

Func<int, int, int> add =
    (a, b) => a + b;

Another:

Func<string, int> length =
    text => text.Length;

The last generic type argument is always the return type.

For:

Func<int, int, int>

read it as:

int → parameter
int → parameter
int → return
21. Func Parameter Limit

Func supports up to 16 input parameters followed by one return type.

Examples:

Func<int, int>
1 parameter
return int
Func<int, int, int>
2 parameters
return int
Func<int, int, int, int>
3 parameters
return int

The final generic argument is always the return type.

22. Lambda and Predicate

Predicate<T> represents a method that:

takes T
returns bool

Example:

Predicate<int> isEven =
    number => number % 2 == 0;

Usage:

Console.WriteLine(isEven(10));

Output:

True

Another:

Predicate<string> isLong =
    text => text.Length > 5;
23. Action, Func, and Predicate

These three are extremely important.

Delegate	Parameters	Return
Action	0	void
Action<T>	1+	void
Func<TResult>	0	TResult
Func<T, TResult>	1+	TResult
Predicate<T>	1	bool

Examples:

Action action =
    () => Console.WriteLine("Hello");
Func<int, int> square =
    x => x * x;
Predicate<int> isEven =
    x => x % 2 == 0;

Mental shortcut:

Action
  ↓
Do something

Func
  ↓
Calculate/return something

Predicate
  ↓
Answer true/false
24. Lambda With Conditional Logic

Lambdas can contain conditional expressions.

Example:

Func<int, string> check =
    age => age >= 18 ? "Adult" : "Minor";

Usage:

Console.WriteLine(check(20));

Output:

Adult

The lambda remains an expression lambda because the body is one expression.

25. Statement Lambda With if

For more complex logic:

Func<int, string> check = age =>
{
    if (age >= 18)
    {
        return "Adult";
    }

    return "Minor";
};

Both versions work.

Use the simpler expression form when the logic remains clear.

26. Lambda With Local Variables

Statement lambdas can contain local variables:

Func<int, int> calculate = number =>
{
    int result = number * 2;

    result += 10;

    return result;
};

The local variable:

result

belongs to the lambda's body.

27. Lambda Can Access Outer Variables

This is one of the deepest concepts.

Consider:

int multiplier = 10;

Func<int, int> multiply =
    number => number * multiplier;

Now:

Console.WriteLine(multiply(5));

Output:

50

The lambda accesses:

multiplier

from its surrounding scope.

This is called capturing a variable.

28. Closures

When a lambda captures a variable from its surrounding scope, the lambda forms a closure over that variable.

Example:

int multiplier = 10;

Func<int, int> multiply =
    number => number * multiplier;

Conceptually:

Closure
 ├── lambda: number => number * multiplier
 └── captured variable: multiplier

The lambda doesn't simply copy the current value in the simplistic sense.

The captured local is lifted into compiler-generated state so that the lambda can continue to access it.

This becomes important when the variable changes.

29. Captured Variable Can Change

Example:

int multiplier = 10;

Func<int, int> multiply =
    number => number * multiplier;

Console.WriteLine(multiply(5));

multiplier = 20;

Console.WriteLine(multiply(5));

Output:

50
100

Why?

Because the lambda captures the variable itself through closure state.

Conceptually:

First:
multiplier = 10
      ↓
5 × 10 = 50

Then:
multiplier = 20
      ↓
5 × 20 = 100

This is a very important distinction.

30. Closure Is Not the Same as Copying a Value

Consider:

int x = 10;

Func<int> getValue = () => x;

x = 20;

Console.WriteLine(getValue());

Output:

20

The lambda observes the captured variable's current value.

This surprises many beginners.

Remember:

A captured local behaves as shared closure state, not simply as a frozen snapshot.

31. Multiple Lambdas Can Share Captured State

Example:

int count = 0;

Action increment =
    () => count++;

Func<int> getCount =
    () => count;

Now:

increment();
increment();
increment();

Console.WriteLine(getCount());

Output:

3

Both lambdas access the same captured count.

Conceptually:

        closure
       /       \
      ↓         ↓
 increment    getCount
      \         /
       ↓       ↓
       count
32. Closure and Lifetime

Normally, a local variable belongs to a method invocation.

But if a lambda captures it and survives beyond that method's execution, the compiler ensures the captured state remains available.

Example:

static Func<int> CreateCounter()
{
    int count = 0;

    return () =>
    {
        count++;
        return count;
    };
}

Usage:

Func<int> counter = CreateCounter();

Console.WriteLine(counter());
Console.WriteLine(counter());
Console.WriteLine(counter());

Output:

1
2
3

The count variable survives because it is part of the closure state.

33. A Powerful Example — Creating a Counter
static Func<int> CreateCounter()
{
    int count = 0;

    return () => ++count;
}

Then:

var counter1 = CreateCounter();
var counter2 = CreateCounter();

Now:

Console.WriteLine(counter1());
Console.WriteLine(counter1());

Console.WriteLine(counter2());

Output:

1
2
1

Why?

Because each call to CreateCounter() creates separate closure state.

counter1
   ↓
count = 2

counter2
   ↓
count = 1

They don't share the same captured variable.

34. Lambda and Collections

Suppose:

List<int> numbers =
    new List<int> { 1, 2, 3, 4, 5 };

You can use a lambda with a method that accepts a delegate.

For example:

numbers.ForEach(
    number => Console.WriteLine(number));

The lambda:

number => Console.WriteLine(number)

provides the behavior for each element.

This is one of the first places you will see lambdas used heavily.

35. Lambda and List<T>.Find

You can write:

int result = numbers.Find(
    number => number > 3);

The lambda:

number => number > 3

answers:

"Does this number satisfy my condition?"

This is essentially predicate-style behavior.

36. Lambda and Events

Lambdas can also subscribe to events.

Suppose:

button.Clicked += OnClicked;

Instead, you can write:

button.Clicked += () =>
{
    Console.WriteLine("Button clicked.");
};

For an EventHandler event:

button.Clicked += (sender, e) =>
{
    Console.WriteLine("Button clicked.");
};

This is convenient when the handler is small and local.

37. Lambda and Event Unsubscription

There is an important catch.

This:

button.Clicked += () =>
{
    Console.WriteLine("Clicked");
};

and later:

button.Clicked -= () =>
{
    Console.WriteLine("Clicked");
};

does not reliably remove the original subscription.

Why?

Because these are separate delegate instances.

For reliable unsubscription, keep the handler reference:

Action handler = () =>
{
    Console.WriteLine("Clicked");
};

Then:

button.Clicked += handler;

and later:

button.Clicked -= handler;

This is especially important for long-lived event publishers.

38. Lambda Type Inference

Consider:

Func<int, int> square = x => x * x;

The compiler knows:

Func<int, int>
     ↓
parameter x = int
return      = int

Therefore you don't need:

(int x) => x * x

This makes lambda syntax compact.

39. Lambda Does Not Mean "Any Function"

A lambda must have a compatible target type.

For example:

Func<int, int> operation =
    x => x * 2;

works.

But if the expected delegate requires:

Func<string, bool>

then:

x => x * 2

does not make sense because the parameter would be a string.

The surrounding target type determines how the lambda is interpreted.

40. Method Group vs Lambda

You learned delegates previously.

Consider:

static int Add(int a, int b)
{
    return a + b;
}

You can write:

Func<int, int, int> operation = Add;

This is a method group conversion.

Or:

Func<int, int, int> operation =
    (a, b) => a + b;

This is a lambda expression.

The difference:

Add
 ↓
existing named method

(a, b) => a + b
 ↓
inline anonymous behavior
41. Lambda vs Anonymous Method

You already saw anonymous methods:

Action action = delegate
{
    Console.WriteLine("Hello");
};

Lambda:

Action action =
    () => Console.WriteLine("Hello");

Lambda expressions are generally the modern, concise syntax for function-like behavior.

Conceptually:

Anonymous method
      ↓
delegate { ... }

Lambda
      ↓
(...) => ...
42. Lambda and Variable Capture — Loop Example

A classic area of confusion involves loops.

Consider:

var actions = new List<Action>();

for (int i = 0; i < 3; i++)
{
    actions.Add(() => Console.WriteLine(i));
}

The lambdas capture the loop variable.

Modern C# gives foreach iteration variables per iteration, but for loop capture behavior is important to understand.

The key lesson is:

Lambdas capture variables, so always reason about the lifetime and identity of the captured variable rather than assuming the lambda stores an independent value.

If you need a snapshot-like value inside a loop, create a separate local:

for (int i = 0; i < 3; i++)
{
    int current = i;

    actions.Add(
        () => Console.WriteLine(current));
}

Now each lambda captures its own current.

Put everything together:

Action<string> print =

44. Real-World Example

Suppose an application has a collection of employees.

List<string> employees =
    new List<string>
    {
        "Alice",
        "Bob",
        "Charlie"
    };

Suppose we want to print every employee:

employees.ForEach(
    employee => Console.WriteLine(employee));

The lambda provides the behavior:

ForEach
  ↓
"Here is each employee"
  ↓
lambda decides what to do

This same concept becomes much more powerful with LINQ.

45. Lambda Is the Bridge to LINQ

This is extremely important for your upcoming lessons.

Consider:

numbers.Where(
    number => number > 10);

The lambda:

number => number > 10

defines the filtering rule.

Or:

numbers.Select(
    number => number * 2);

The lambda:

number => number * 2

defines the transformation.

So:

Lambda
   ↓
Func / Predicate
   ↓
LINQ
   ↓
Where / Select / OrderBy / GroupBy / Join

You will understand LINQ much more easily because you now understand delegates and lambdas.

46. Common Lambda Mistakes
Mistake 1 — Forgetting the target type

This by itself doesn't work as a normal standalone variable declaration:

var operation = x => x * 2;

A lambda needs a target delegate type in this situation.

Instead:

Func<int, int> operation =
    x => x * 2;
Mistake 2 — Incorrect return

Wrong:

Func<int, int> square =
    x =>
    {
        x * x;
    };

The block needs return:

Func<int, int> square =
    x =>
    {
        return x * x;
    };
Mistake 3 — Wrong delegate type
Action<int> operation =
    x => x * 2;

This doesn't work because Action<int> expects a void-returning lambda.

Use:

Func<int, int> operation =
    x => x * 2;
Mistake 4 — Confusing Func argument order

This:

Func<int, int, bool>

means:

int parameter
int parameter
bool return

Not:

bool parameter

Remember:

The last type parameter of Func is the return type.

     ↓

     ↓

     ↓

     ↓

The fundamental idea remains the same:

A lambda is a compact way to provide executable behavior where a compatible delegate type is expected.
