Inheritance

Inheritance is the first major topic of Module 2.

You already know classes and objects. Now we will build on that foundation and understand how one class can derive from another.

1. What Is Inheritance?

Inheritance allows a class to derive from another class and reuse its accessible members while adding or changing behavior.

Example:

class Animal
{
    public void Eat()
    {
        Console.WriteLine("Eating");
    }
}

class Dog : Animal
{
    public void Bark()
    {
        Console.WriteLine("Barking");
    }
}

Here:

Animal
   ↑
   │
  Dog
Animal → base class
Dog → derived class
Dog : Animal → Dog inherits from Animal

Now:

Dog dog = new Dog();

dog.Eat();
dog.Bark();

Output:

Eating
Barking

Eat() belongs to Animal, but Dog can use it because Dog derives from Animal.

2. Why Do We Need Inheritance?

Imagine we have:

class Dog
{
    public void Eat()
    {
        Console.WriteLine("Eating");
    }

    public void Sleep()
    {
        Console.WriteLine("Sleeping");
    }

    public void Bark()
    {
        Console.WriteLine("Barking");
    }
}

And:

class Cat
{
    public void Eat()
    {
        Console.WriteLine("Eating");
    }

    public void Sleep()
    {
        Console.WriteLine("Sleeping");
    }

    public void Meow()
    {
        Console.WriteLine("Meowing");
    }
}

Both classes contain:

Eat()
Sleep()

This creates duplicated code.

We can move common behavior into a base class:

class Animal
{
    public void Eat()
    {
        Console.WriteLine("Eating");
    }

    public void Sleep()
    {
        Console.WriteLine("Sleeping");
    }
}

class Dog : Animal
{
    public void Bark()
    {
        Console.WriteLine("Barking");
    }
}

class Cat : Animal
{
    public void Meow()
    {
        Console.WriteLine("Meowing");
    }
}

Now:

                 Animal
                /      \
               /        \
            Dog          Cat
             |            |
           Bark()        Meow()

Animal:
    Eat()
    Sleep()

The common functionality exists in one place.

3. The Most Important Concept: IS-A

Inheritance usually represents an IS-A relationship.

Examples:

Dog IS-A Animal
Cat IS-A Animal
Manager IS-A Employee
Car IS-A Vehicle
SavingsAccount IS-A BankAccount

For example:

class Vehicle
{
}

class Car : Vehicle
{
}

We can say:

Car IS-A Vehicle

This is a strong indication that inheritance may be appropriate.

4. Inheritance Syntax

The basic syntax is:

class DerivedClass : BaseClass
{
}

Example:

class Employee
{
    public string Name;
}

class Manager : Employee
{
    public void Manage()
    {
        Console.WriteLine("Managing");
    }
}

Here:

Employee
   ↑
Manager

Manager inherits from Employee.

5. What Does the Derived Class Get?

Consider:

class Employee
{
    public string Name;

    public void Work()
    {
        Console.WriteLine("Working");
    }
}

class Manager : Employee
{
    public void Manage()
    {
        Console.WriteLine("Managing");
    }
}

Now:

Manager manager = new Manager();

manager.Name = "John";
manager.Work();
manager.Manage();

Manager has access to:

Name     → inherited
Work()   → inherited
Manage() → Manager's own member

Conceptually:

Manager
├── Own members
│   └── Manage()
│
└── Inherited accessible members
    ├── Name
    └── Work()
6. Inheritance Is Not Code Copying

Do not think:

"C# copies all the code from the parent class into the child class."

That is not the right mental model.

Instead:

Manager
   ↓
is derived from
   ↓
Employee

There is a relationship between the types.

Because of this relationship, the derived class can use inherited accessible members.

This distinction becomes extremely important when we reach polymorphism.

7. Access Modifiers and Inheritance

Inheritance does not mean that the child can access everything from the parent.

Consider:

class Animal
{
    public string Name;
    private int age;
    protected string Species;
}

Derived class:

class Dog : Animal
{
    public void Test()
    {
        Name = "Tommy";       // Allowed
        Species = "Dog";      // Allowed

        // age = 5;           // Not allowed
    }
}

Why?

Because access modifiers still apply.

8. public

A public member is accessible from outside the class, assuming normal type accessibility.

class Animal
{
    public void Eat()
    {
        Console.WriteLine("Eating");
    }
}

Both the derived class and outside code can use it:

Dog dog = new Dog();

dog.Eat();

Mental model:

public
   ↓
Generally accessible from outside
9. private

A private member belongs only to the class that declares it.

class Animal
{
    private int age;
}

A derived class cannot directly access it:

class Dog : Animal
{
    public void Test()
    {
        // age = 5;   // Error
    }
}

Important:

Inheritance does not remove private access restrictions.

10. protected

protected is especially important for inheritance.

class Animal
{
    protected string name;
}

A derived class can access it:

class Dog : Animal
{
    public void SetName()
    {
        name = "Tommy";
    }
}

But normal outside code cannot directly access it:

Dog dog = new Dog();

// dog.name = "Tommy";   // Error

Mental model:

private
    ↓
Declaring class

protected
    ↓
Declaring class
+
Derived classes

public
    ↓
Generally accessible
11. Creating a Derived Object

Example:

class Animal
{
    public void Eat()
    {
        Console.WriteLine("Eating");
    }
}

class Dog : Animal
{
    public void Bark()
    {
        Console.WriteLine("Barking");
    }
}

Create:

Dog dog = new Dog();

Then:

dog.Eat();
dog.Bark();

The object is a Dog, but it also has the inherited Animal behavior.

12. Base-Type Reference

Now we reach a very important concept.

Because:

Dog IS-A Animal

this is valid:

Animal animal = new Dog();

Think about the two sides separately:

Animal animal
     ↑
Reference type

new Dog()
     ↑
Actual object type

So:

Reference type → Animal
Actual object  → Dog

You can do:

animal.Eat();

because Eat() exists in Animal.

But if Bark() exists only in Dog:

animal.Bark(); // Error

The reference is typed as Animal.

This concept will become critical when we study:

virtual + override + polymorphism

13. Constructors and Inheritance

Now we move to one of the most important parts of this lesson.

Consider:

class Animal
{
    public Animal()
    {
        Console.WriteLine("Animal constructor");
    }
}

class Dog : Animal
{
    public Dog()
    {
        Console.WriteLine("Dog constructor");
    }
}

Now:

Dog dog = new Dog();

Output:

Animal constructor
Dog constructor

Not:

Dog constructor
Animal constructor
14. Why Does the Base Constructor Run First?

A Dog contains the inherited/base part associated with Animal.

Before the derived class finishes constructing itself, the base portion must be initialized.

Think:

new Dog()
    ↓
Construct base portion
    ↓
Animal constructor
    ↓
Construct derived portion
    ↓
Dog constructor
    ↓
Dog object ready

Therefore:

The base constructor executes before the derived constructor.

15. Constructor Chaining

Now suppose the base class has a parameterized constructor:

class Animal
{
    public Animal(string name)
    {
        Console.WriteLine($"Animal: {name}");
    }
}

The derived class can call it using base(...):

class Dog : Animal
{
    public Dog(string name)
        : base(name)
    {
        Console.WriteLine($"Dog: {name}");
    }
}

Now:

Dog dog = new Dog("Tommy");

Output:

Animal: Tommy
Dog: Tommy

This:

: base(name)

is called constructor chaining to the base class.

16. What Does base(...) Mean?

When used after a constructor declaration:

public Dog(string name)
    : base(name)
{
}

it means:

Call the constructor of the base class with these arguments.

So:

Dog constructor
      ↓
base(name)
      ↓
Animal(string name)
17. Why Is base(...) Sometimes Required?

Consider:

class Animal
{
    public Animal(string name)
    {
        Console.WriteLine(name);
    }
}

class Dog : Animal
{
    public Dog(string name)
    {
    }
}

The base class has only:

Animal(string name)

There is no parameterless:

Animal()

constructor.

So the derived class must specify which base constructor to call:

class Dog : Animal
{
    public Dog(string name)
        : base(name)
    {
    }
}

Now the compiler knows exactly what to do.

18. base() vs base(argument)

If the base class has a parameterless constructor:

class Animal
{
    public Animal()
    {
    }
}

you can explicitly write:

class Dog : Animal
{
    public Dog()
        : base()
    {
    }
}

But base() can normally be omitted:

class Dog : Animal
{
    public Dog()
    {
    }
}

The parameterless base constructor is selected automatically.

However, if the base constructor requires an argument:

Animal(string name)

you need:

: base(name)
19. base Has Two Different Jobs

This is extremely important.

Job 1 — Call Base Constructor
public Dog(string name)
    : base(name)
{
}

Meaning:

Call base constructor
Job 2 — Access Base Member
base.Eat();

Meaning:

Call the base class's member

So remember:

base(...)
    ↓
Base constructor

base.Member
    ↓
Base class member
20. Calling a Base Method

Consider:

class Animal
{
    public void Eat()
    {
        Console.WriteLine("Animal eating");
    }
}

class Dog : Animal
{
    public void Eat()
    {
        Console.WriteLine("Dog eating");
    }

    public void Test()
    {
        Eat();
        base.Eat();
    }
}

Now:

Dog dog = new Dog();

dog.Test();

Output:

Dog eating
Animal eating

Why?

Eat();

means:

Use the current class's accessible Eat().

While:

base.Eat();

means:

Explicitly use the base class's Eat().

21. this vs base

You already learned this.

Now compare them:

Keyword	Meaning
this	Current object/current class
base	Base-class part/member

Examples:

this.name

means:

The current object's name.

While:

base.SomeMethod()

means:

Call the base class's implementation.

And:

: base(value)

means:

Call the base class constructor.

22. Multi-Level Inheritance

Inheritance can have multiple levels.

class Animal
{
}

class Mammal : Animal
{
}

class Dog : Mammal
{
}

Relationship:

Animal
   ↑
Mammal
   ↑
Dog

Therefore:

Dog IS-A Mammal
Dog IS-A Animal
23. Constructor Order in Multi-Level Inheritance

Consider:

class Animal
{
    public Animal()
    {
        Console.WriteLine("Animal");
    }
}

class Mammal : Animal
{
    public Mammal()
    {
        Console.WriteLine("Mammal");
    }
}

class Dog : Mammal
{
    public Dog()
    {
        Console.WriteLine("Dog");
    }
}

Create:

Dog dog = new Dog();

Output:

Animal
Mammal
Dog

The construction order is:

Top-level base
      ↓
Intermediate class
      ↓
Derived class

Or:

Animal constructor
       ↓
Mammal constructor
       ↓
Dog constructor
24. Constructors Are Not Inherited

This is a very important rule.

Consider:

class Animal
{
    public Animal(string name)
    {
    }
}

class Dog : Animal
{
}

Dog does not automatically inherit:

Animal(string name)

Constructors are not inherited.

If Dog needs a constructor that accepts the name:

class Dog : Animal
{
    public Dog(string name)
        : base(name)
    {
    }
}

Remember:

Methods / properties
    ↓
May be inherited

Constructors
    ↓
Are not inherited
25. One Base Class Only

C# does not allow a class to directly inherit from multiple classes.

This is invalid:

class Dog : Animal, Mammal
{
}

A class can have only one direct base class:

class Dog : Animal
{
}

However, a class can implement multiple interfaces:

class Dog : Animal, IRunnable, ISwimmable
{
}

We will study this carefully when we reach Interfaces.

26. Inheritance vs Composition

This distinction becomes increasingly important as your C# knowledge grows.

Inheritance:

IS-A

Composition:

HAS-A

Example:

Dog IS-A Animal

Inheritance makes sense:

class Dog : Animal
{
}

But:

Car HAS-A Engine

does not mean:

class Car : Engine
{
}

Instead:

class Car
{
    private Engine engine;
}

So:

IS-A  → Inheritance
HAS-A → Composition

Choosing between these is an important software design skill.

27. Inheritance and Encapsulation

Inheritance should not force the parent to expose all its internal data.

Bad design:

class BankAccount
{
    public decimal balance;
}

Now derived classes and external code can directly modify the balance.

Better:

class BankAccount
{
    private decimal balance;

    protected void ChangeBalance(decimal amount)
    {
        balance += amount;
    }
}

Derived class:

class SavingsAccount : BankAccount
{
    public void AddInterest(decimal interest)
    {
        ChangeBalance(interest);
    }
}

Here:

balance
   ↓
private
   ↓
protected from direct external access

ChangeBalance()
   ↓
controlled operation
   ↓
available to derived classes

This combines inheritance + encapsulation.

28. A Complete Example

Let's combine inheritance, protected, constructors, and base.

class Employee
{
    protected string name;

    public Employee(string name)
    {
        this.name = name;
        Console.WriteLine("Employee constructor");
    }

    public void ShowName()
    {
        Console.WriteLine($"Name: {name}");
    }

    public void Work()
    {
        Console.WriteLine("Employee working");
    }
}

Derived class:

class Manager : Employee
{
    public Manager(string name)
        : base(name)
    {
        Console.WriteLine("Manager constructor");
    }

    public void Manage()
    {
        Console.WriteLine($"{name} is managing");
    }
}

Usage:

Manager manager = new Manager("John");

manager.ShowName();
manager.Work();
manager.Manage();

Output:

Employee constructor
Manager constructor
Name: John
Employee working
John is managing

The flow:

new Manager("John")
        ↓
base("John")
        ↓
Employee constructor
        ↓
Manager constructor
        ↓
Manager object ready
        ↓
ShowName()
Work()
Manage()
29. A Critical Preview: Inheritance vs Polymorphism

You will soon learn:

virtual
override
new

Do not confuse these with inheritance itself.

Inheritance:

Dog : Animal

establishes the relationship.

Polymorphism:

virtual
override

controls how behavior can vary through that relationship.

For example:

class Animal
{
    public virtual void MakeSound()
    {
        Console.WriteLine("Animal sound");
    }
}

class Dog : Animal
{
    public override void MakeSound()
    {
        Console.WriteLine("Bark");
    }
}

We will study exactly why this behaves differently from ordinary method hiding later.

30. Common Mistakes
Mistake 1 — Thinking private members are directly accessible
class Parent
{
    private int value;
}

class Child : Parent
{
    // value = 10; // Error
}

Inheritance does not bypass private.

Mistake 2 — Forgetting base(...)

If the base class has no parameterless constructor:

class Parent
{
    public Parent(string name)
    {
    }
}

the derived class must correctly chain to it.

class Child : Parent
{
    public Child(string name)
        : base(name)
    {
    }
}
Mistake 3 — Thinking constructors are inherited

They aren't.

Each class defines its own constructors.

Mistake 4 — Using inheritance for HAS-A relationships
Car HAS-A Engine

doesn't mean:

class Car : Engine
Mistake 5 — Confusing inheritance with overriding

These are different:

Inheritance
    ↓
class Dog : Animal

Overriding
    ↓
override method

Overriding is part of polymorphism, which is a later topic.

32. Key Takeaways
1. Inheritance allows one class to derive from another.

2. Syntax:
   class Child : Parent

3. Parent = base class.
   Child = derived class.

4. Inheritance generally represents an IS-A relationship.

5. Derived classes can use accessible inherited members.

6. private members are not directly accessible from derived classes.

7. protected members are accessible to derived classes.

8. Constructors are not inherited.

9. Base constructors execute before derived constructors.

10. base(...) calls a base constructor.

11. base.Member accesses a base member.

12. C# allows only one direct base class.

13. Multiple interfaces are possible.

14. Do not use inheritance for HAS-A relationships.

15. Inheritance establishes the relationship;
    polymorphism determines how behavior can vary.
