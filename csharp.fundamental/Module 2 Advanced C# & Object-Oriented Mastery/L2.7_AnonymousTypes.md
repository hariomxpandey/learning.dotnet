Anonymous Types
1. What Is an Anonymous Type?

An anonymous type is a compiler-generated type that lets you create an object without explicitly declaring a class for it.

Example:

var person = new
{
    Name = "Hariom",
    Age = 22
};

We did not create:

class Person
{
    public string Name { get; set; }
    public int Age { get; set; }
}

Instead, C# creates an unnamed type for us.

The type has no name that you write in your source code.

2. Why Do Anonymous Types Exist?

Suppose you only need a small temporary object:

var person = new
{
    Name = "Hariom",
    Age = 22
};

Creating a complete class for this temporary data may be unnecessary.

Anonymous types are especially useful when:

selecting a few properties from objects
creating temporary data structures
working with LINQ
shaping query results
passing around temporary read-only data inside a method

The biggest connection is:

Anonymous Types
       ↓
temporary object shapes
       ↓
LINQ
       ↓
Select(...)
       ↓
project only the data you need

This is why anonymous types are taught immediately before LINQ.

3. Basic Syntax
var person = new
{
    Name = "Hariom",
    Age = 22
};

The syntax is:

var variable = new
{
    Property1 = value1,
    Property2 = value2
};

For example:

var product = new
{
    Id = 101,
    Name = "Laptop",
    Price = 75000
};

You can access the properties normally:

Console.WriteLine(product.Id);
Console.WriteLine(product.Name);
Console.WriteLine(product.Price);

Output:

101
Laptop
75000
4. Why Do We Use var?

Consider:

var person = new
{
    Name = "Hariom",
    Age = 22
};

What is the type of person?

There is a type, but you don't have a source-level name for that type.

The compiler generates an anonymous type internally.

Therefore, you normally use:

var

instead of trying to write its type.

You cannot write something meaningful like:

AnonymousPerson person = new AnonymousPerson();

because you didn't define such a type.

5. var Does NOT Mean Dynamic

This is extremely important.

Some beginners think:

var person = new
{
    Name = "Hariom",
    Age = 22
};

means:

"The type will be decided at runtime."

That is incorrect.

var is statically typed.

The compiler determines the type at compile time.

For example:

var age = 22;

The compiler knows:

age → int

Similarly:

var person = new
{
    Name = "Hariom",
    Age = 22
};

The compiler knows the anonymous type's structure at compile time.

So:

person.Name

is checked by the compiler.

6. Anonymous Types Are Strongly Typed

Consider:

var person = new
{
    Name = "Hariom",
    Age = 22
};

This works:

Console.WriteLine(person.Name);
Console.WriteLine(person.Age);

But this does not:

Console.WriteLine(person.Salary);

because the anonymous type doesn't contain a Salary property.

The compiler catches the problem.

So anonymous types are still strongly typed.

7. Properties Are Read-Only

This is one of the most important characteristics.

Consider:

var person = new
{
    Name = "Hariom",
    Age = 22
};

You can read:

Console.WriteLine(person.Name);

But you cannot do:

person.Name = "Rahul";

This produces a compiler error.

Anonymous type properties are effectively read-only after the object is created.

Think:

Create
  ↓
Anonymous object
  ↓
Read properties
  ↓
Cannot modify properties
8. Anonymous Type Is Not Immutable in Every Possible Sense

Be precise here.

Anonymous type properties are read-only, but that doesn't automatically mean every referenced object inside it is deeply immutable.

For example:

var person = new
{
    Name = "Hariom",
    Skills = new List<string>
    {
        "C#",
        "SQL"
    }
};

You cannot replace:

person.Skills = new List<string>();

But you can modify the list itself:

person.Skills.Add("LINQ");

So:

Anonymous property
      ↓
read-only reference

Referenced object
      ↓
may still be mutable

This distinction is important.

9. Property Type Inference

You don't always need to explicitly specify property names.

For example:

string name = "Hariom";
int age = 22;

var person = new
{
    name,
    age
};

C# automatically creates properties based on the variable names.

Conceptually:

var person = new
{
    name = name,
    age = age
};

Therefore:

Console.WriteLine(person.name);
Console.WriteLine(person.age);

works.

10. Explicit Property Names

You can also choose different property names:

string name = "Hariom";
int age = 22;

var person = new
{
    Name = name,
    Age = age
};

Now:

person.Name
person.Age

are the property names.

This is often clearer when shaping data.

11. Expressions Can Be Used

Anonymous type properties don't have to come directly from variables.

You can use expressions:

int price = 100;
int quantity = 3;

var order = new
{
    Price = price,
    Quantity = quantity,
    Total = price * quantity
};

Now:

Console.WriteLine(order.Total);

Output:

300

The anonymous type is simply describing the resulting data shape.

12. Anonymous Types Can Contain Different Data Types

For example:

var data = new
{
    Id = 101,
    Name = "Laptop",
    Price = 75000.50m,
    InStock = true
};

The compiler creates properties with appropriate types:

Id       → int
Name     → string
Price    → decimal
InStock  → bool

You don't need to declare a separate class just to hold this temporary combination.

13. Nested Anonymous Types

Anonymous types can contain other anonymous types.

var person = new
{
    Name = "Hariom",
    Address = new
    {
        City = "Varanasi",
        Country = "India"
    }
};

Access:

Console.WriteLine(person.Name);
Console.WriteLine(person.Address.City);
Console.WriteLine(person.Address.Country);

This creates a nested data structure.

Mental model:

person
├── Name
└── Address
    ├── City
    └── Country
14. Anonymous Types Inside Methods

This is where anonymous types are most comfortable.

static void ShowPerson()
{
    var person = new
    {
        Name = "Hariom",
        Age = 22
    };

    Console.WriteLine(person.Name);
    Console.WriteLine(person.Age);
}

The anonymous type is local to the method's implementation.

This is a very common use case.

15. Returning an Anonymous Type

This is where things become important.

You cannot normally write:

static ??? GetPerson()
{
    return new
    {
        Name = "Hariom",
        Age = 22
    };
}

What would ??? be?

You don't have a source-level name for the anonymous type.

So anonymous types are generally intended for local use, particularly inside the method where they are created.

16. Why Anonymous Types Work Well With LINQ

Suppose we have:

class Product
{
    public int Id { get; set; }
    public string Name { get; set; }
    public decimal Price { get; set; }
}

And:

List<Product> products = new List<Product>
{
    new Product
    {
        Id = 1,
        Name = "Laptop",
        Price = 75000
    },
    new Product
    {
        Id = 2,
        Name = "Mouse",
        Price = 1000
    }
};

Maybe we don't need the entire Product.

We only need:

Name
Price

Later with LINQ:

var result = products.Select(p => new
{
    p.Name,
    p.Price
});

This creates a new anonymous type containing only:

Name
Price

This process is called projection.

17. Projection — Important LINQ Concept

Suppose original data is:

Product
├── Id
├── Name
├── Price
├── Category
├── Stock
└── Supplier

But you only need:

Name
Price

LINQ can project:

var result = products.Select(p => new
{
    p.Name,
    p.Price
});

Conceptually:

Original Product
      │
      │ Select
      ▼
Anonymous object
┌──────────────┐
│ Name         │
│ Price        │
└──────────────┘

This is one of the most important reasons anonymous types exist.

18. Anonymous Type Equality

This is a deeper and useful behavior.

Consider:

var a = new
{
    Name = "Hariom",
    Age = 22
};

var b = new
{
    Name = "Hariom",
    Age = 22
};

These are created with the same property names and compatible property types in the same order.

The compiler can use the same anonymous type shape.

Anonymous types provide value-based equality behavior for their properties.

Therefore:

Console.WriteLine(a.Equals(b));

can produce:

True

because the property values are equal.

19. Property Names and Types Matter

Consider:

var a = new
{
    Name = "Hariom",
    Age = 22
};

var b = new
{
    Name = "Hariom",
    Age = 22
};

Same shape.

Now:

var c = new
{
    Name = "Hariom",
    Salary = 50000
};

Different property shape.

Conceptually:

a → { Name:string, Age:int }

b → { Name:string, Age:int }

c → { Name:string, Salary:int }

a and b have the same anonymous type shape.

c has a different shape.

20. Property Order Matters for Anonymous Type Identity

Consider:

var a = new
{
    Name = "Hariom",
    Age = 22
};

and:

var b = new
{
    Age = 22,
    Name = "Hariom"
};

Although the properties have the same names and values, the declared property order is part of the anonymous type shape.

So you should not think of anonymous types as simply unordered dictionaries.

They are compiler-generated strongly typed objects.

21. Anonymous Type vs Dictionary

These are very different.

Anonymous type
var person = new
{
    Name = "Hariom",
    Age = 22
};

Access:

person.Name
Dictionary
var person = new Dictionary<string, object>
{
    ["Name"] = "Hariom",
    ["Age"] = 22
};

Access:

person["Name"]

Anonymous types give you:

compile-time property checking
property syntax
known structure
strong typing

Dictionary gives you:

dynamic keys
runtime lookup
flexible structure

Use them for different purposes.

22. Anonymous Type vs Named Class
Anonymous type
var person = new
{
    Name = "Hariom",
    Age = 22
};

Good for:

temporary data
local transformations
LINQ projections
short-lived internal data
Named class
public class Person
{
    public string Name { get; set; }
    public int Age { get; set; }
}

Good for:

reusable domain models
public APIs
method boundaries
long-lived data structures
business logic
serialization contracts

Mental rule:

Temporary shape
     ↓
Anonymous type

Reusable concept
     ↓
Named class/record
23. Anonymous Type vs dynamic

This distinction is extremely important.

Anonymous type
var person = new
{
    Name = "Hariom",
    Age = 22
};

Compile-time type checking.

Dynamic
dynamic person = new
{
    Name = "Hariom",
    Age = 22
};

Now member resolution happens dynamically at runtime.

For example:

Console.WriteLine(person.UnknownProperty);

The compiler doesn't reject it in the same way; the failure occurs at runtime.

So:

Anonymous type
     ↓
strongly typed
     ↓
compile-time checking

dynamic
     ↓
runtime binding
     ↓
runtime errors possible

Do not confuse these.

24. Anonymous Types Are Usually Internal Implementation Details

Imagine a method internally does:

var result = new
{
    Name = "Hariom",
    Age = 22
};

The anonymous type is generally an implementation detail.

If other parts of your application need to understand this structure, a named type is usually more appropriate.

For example:

public class PersonSummary
{
    public string Name { get; set; }
    public int Age { get; set; }
}

Now the type has a meaningful identity.

25. Anonymous Types and Method Boundaries

A useful rule:

Anonymous types are most comfortable inside the method where they are created.

For example:

static void Process()
{
    var data = new
    {
        Name = "Hariom",
        Score = 95
    };

    Console.WriteLine(data.Name);
}

Perfectly reasonable.

But designing a public API around an anonymous type is usually not the right approach.

If consumers need to know the structure, create a named type.

26. Anonymous Types Are Reference Types

Anonymous types are compiler-generated reference types.

So:

var person = new
{
    Name = "Hariom"
};

creates an object on the managed heap, just like other class instances.

The variable:

person

holds a reference to that object.

27. Anonymous Type Members Are Properties

Consider:

var person = new
{
    Name = "Hariom",
    Age = 22
};

These aren't fields that you manually declared.

They are generated properties.

Conceptually similar to:

public string Name { get; }
public int Age { get; }

This explains why you can read them but not assign new values after construction.

28. A Practical Example

Imagine processing order information:

int quantity = 3;
decimal price = 1000;

var orderSummary = new
{
    Quantity = quantity,
    Price = price,
    Total = quantity * price,
    IsLargeOrder = quantity >= 3
};

Now:

Console.WriteLine(orderSummary.Quantity);
Console.WriteLine(orderSummary.Price);
Console.WriteLine(orderSummary.Total);
Console.WriteLine(orderSummary.IsLargeOrder);

Output:

3
1000
3000
True

No separate class was necessary because this object is only being used as a temporary summary.

29. Common Mistakes
Mistake 1 — Thinking var means dynamic

Wrong:

var means the type is unknown until runtime.

Correct:

var means the compiler infers the static type at compile time.

Mistake 2 — Trying to Modify Anonymous Properties
var person = new
{
    Name = "Hariom"
};

person.Name = "Rahul";

Not allowed.

The property is read-only.

Mistake 3 — Using Anonymous Types Everywhere

Anonymous types are not a replacement for classes.

Don't create:

var customer = new
{
    ...
};

everywhere when Customer is a meaningful reusable domain concept.

Mistake 4 — Expecting Easy Public API Usage

Anonymous types don't have a source-level name.

They're therefore awkward as reusable method contracts.

Mistake 5 — Confusing Anonymous Types With dynamic

They are fundamentally different:

anonymous type → compile-time type safety

dynamic        → runtime binding
30. The Big Connection to LINQ

This is the concept you should carry into the next lesson.

Suppose:

List<Product> products

contains:

Id
Name
Price
Category
Stock

You only need:

Name
Price

LINQ allows:

var result = products.Select(p => new
{
    p.Name,
    p.Price
});

Now each result item has a temporary shape:

{
    Name,
    Price
}

So:

Lambda
   +
Anonymous Type
   +
Extension Method
   ↓
LINQ

This is the bridge into the next major topic.

31. Complete Example
using System;
using System.Collections.Generic;
using System.Linq;

class Product
{
    public int Id { get; set; }
    public string Name { get; set; }
    public decimal Price { get; set; }
}

class Program
{
    static void Main()
    {
        List<Product> products = new List<Product>
        {
            new Product
            {
                Id = 1,
                Name = "Laptop",
                Price = 75000
            },
            new Product
            {
                Id = 2,
                Name = "Mouse",
                Price = 1000
            },
            new Product
            {
                Id = 3,
                Name = "Keyboard",
                Price = 2500
            }
        };

        var result = products.Select(product => new
        {
            product.Name,
            product.Price
        });

        foreach (var item in result)
        {
            Console.WriteLine(
                $"{item.Name} - {item.Price}");
        }
    }
}

Output:

Laptop - 75000
Mouse - 1000
Keyboard - 2500

Notice the three concepts working together:

products.Select(...)
       │
       │ extension method
       ▼
lambda expression
       │
       ▼
new { ... }
       │
       ▼
anonymous type

This is the foundation for LINQ.
