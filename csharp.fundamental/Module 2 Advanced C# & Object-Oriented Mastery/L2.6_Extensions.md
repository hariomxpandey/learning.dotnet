Extension Methods
1. What Is an Extension Method?

An extension method allows you to add a method-like capability to an existing type without modifying the original type and without creating a derived class.

For example, suppose you want this:

string name = "Hariom";

bool result = name.IsLongerThan(3);

string does not originally have an IsLongerThan() method.

You can create it as an extension method.

2. Why Do Extension Methods Exist?

Imagine you want to add functionality to:

string
int
List<T>
IEnumerable<T>
a class from a third-party library

But you cannot or should not modify the original class.

Without extension methods, you might write:

public static bool IsLongerThan(string value, int length)
{
    return value.Length > length;
}

Then:

bool result = IsLongerThan("Hello", 3);

This works, but it doesn't look like a method belonging to string.

With an extension method:

bool result = "Hello".IsLongerThan(3);

The syntax becomes much more natural.

3. Basic Syntax

An extension method has three important requirements:

It must be inside a static class.
The method itself must be static.
The first parameter must use the this keyword.
public static class StringExtensions
{
    public static bool IsLongerThan(
        this string value,
        int length)
    {
        return value.Length > length;
    }
}

The important part is:

this string value

The this tells C#:

"This method extends the string type."

4. Using the Extension Method

Suppose we have:

public static class StringExtensions
{
    public static bool IsLongerThan(
        this string value,
        int length)
    {
        return value.Length > length;
    }
}

Now:

string name = "Hariom";

bool result = name.IsLongerThan(3);

Console.WriteLine(result);

Output:

True

You can also directly write:

Console.WriteLine("Hello".IsLongerThan(3));
5. What Does this Mean Here?

This:

public static bool IsLongerThan(
    this string value,
    int length)

means:

The first argument is the object on which the extension method is called.

When you write:

"Hello".IsLongerThan(3);

C# conceptually maps it to:

StringExtensions.IsLongerThan("Hello", 3);

So:

"Hello"

becomes:

value

and:

3

becomes:

length
6. Two Ways to Call It

Given:

public static class StringExtensions
{
    public static bool IsLongerThan(
        this string value,
        int length)
    {
        return value.Length > length;
    }
}
Extension-style call
string text = "Hello";

bool result = text.IsLongerThan(3);
Static-style call

You can also call the method normally:

bool result = StringExtensions.IsLongerThan("Hello", 3);

Both refer to the same static method.

The extension syntax is primarily a more convenient calling syntax.

7. Important: Extension Methods Do NOT Modify the Original Class

This is one of the most important concepts.

Suppose:

public static class StringExtensions
{
    public static bool IsLongerThan(
        this string value,
        int length)
    {
        return value.Length > length;
    }
}

You have not modified System.String.

You have created a separate static method that the compiler allows you to call using instance-style syntax.

Conceptually:

System.String
     │
     │ does not actually contain
     │ IsLongerThan()
     │
     ▼
Extension Method
     │
     ▼
StringExtensions.IsLongerThan(...)

So extension methods are syntactic extension, not actual modification of the type.

8. Extension Method Resolution

This is where extension methods become more interesting.

Consider:

string text = "Hello";

text.IsLongerThan(3);

The compiler needs to determine:

"Where is IsLongerThan()?"

It checks for an actual instance method first.

If it doesn't find one, it searches available extension methods.

Conceptually:

text.IsLongerThan(3)
       │
       ▼
Does string have an instance method?
       │
       ├── Yes → use it
       │
       └── No
            │
            ▼
     Search extension methods
            │
            ▼
     Find compatible extension

This leads to an extremely important rule.

9. Instance Method Has Priority

Suppose a type already has:

public void Print()
{
    Console.WriteLine("Instance method");
}

And you create:

public static class MyExtensions
{
    public static void Print(this MyClass obj)
    {
        Console.WriteLine("Extension method");
    }
}

Now:

MyClass obj = new MyClass();

obj.Print();

Which one runs?

The instance method.

Output:

Instance method

The extension method does not override the instance method.

Rule

An actual instance member takes precedence over an extension method.

This is important when working with large codebases or third-party libraries.

10. Extension Methods Need a Namespace

Suppose your extension class is:

namespace MyExtensions
{
    public static class StringExtensions
    {
        public static bool IsLongerThan(
            this string value,
            int length)
        {
            return value.Length > length;
        }
    }
}

And your program is:

using MyExtensions;

string text = "Hello";

Console.WriteLine(text.IsLongerThan(3));

The:

using MyExtensions;

makes the extension method available to the compiler.

Without the appropriate namespace being in scope, this may fail:

text.IsLongerThan(3);

with a compiler error because the extension method cannot be found.

11. Extension Methods Must Be Static

This is invalid:

public class StringExtensions
{
    public bool IsLongerThan(
        this string value,
        int length)
    {
        return value.Length > length;
    }
}

Why?

Because extension methods must be declared as:

static

Correct:

public static class StringExtensions
{
    public static bool IsLongerThan(
        this string value,
        int length)
    {
        return value.Length > length;
    }
}

Both the class and method are static.

12. Why Must the Class Be Static?

Extension methods are not associated with an object of the extension class.

You don't do this:

StringExtensions extensions = new StringExtensions();

Instead:

"Hello".IsLongerThan(3);

The extension class acts as a container for extension methods.

Think:

StringExtensions
        │
        ├── IsLongerThan()
        ├── IsEmpty()
        ├── ToSomething()
        └── ...

It is a collection of related extension functionality.

13. Extension Method With Multiple Parameters

Only the first parameter uses this.

Example:

public static class StringExtensions
{
    public static bool ContainsIgnoreCase(
        this string value,
        string searchText)
    {
        return value.Contains(
            searchText,
            StringComparison.OrdinalIgnoreCase);
    }
}

Usage:

string text = "Hello World";

bool result = text.ContainsIgnoreCase("hello");

Mapping:

text
 ↓
this string value

"hello"
 ↓
string searchText

So:

text.ContainsIgnoreCase("hello");

is conceptually:

StringExtensions.ContainsIgnoreCase(text, "hello");
14. Generic Extension Methods

Extension methods can also be generic.

Example:

public static class CollectionExtensions
{
    public static bool IsEmpty<T>(
        this IEnumerable<T> collection)
    {
        return !collection.Any();
    }
}

Usage:

List<int> numbers = new List<int>();

Console.WriteLine(numbers.IsEmpty());

Here:

T

is inferred from:

List<int>

So effectively:

T = int

This becomes especially important when you start learning LINQ.

15. Extension Methods on IEnumerable<T>

This is one of the most important real-world uses.

Consider:

List<int> numbers = new List<int>
{
    10, 20, 30, 40, 50
};

You can write:

numbers.Where(x => x > 20);

Where() is an extension method.

It extends:

IEnumerable<T>

This is a major reason extension methods are important in C#.

Later, when you learn LINQ, you'll see methods such as:

Where()
Select()
OrderBy()
GroupBy()
First()
Any()
Count()

Many LINQ operations are implemented as extension methods.

So the relationship is:

Extension Methods
       │
       ▼
IEnumerable<T> extensions
       │
       ▼
LINQ

This is why understanding extension methods before LINQ is important.

16. Example: Creating a Simple LINQ-Like Extension

Consider:

public static class CollectionExtensions
{
    public static int CountGreaterThan(
        this IEnumerable<int> numbers,
        int value)
    {
        int count = 0;

        foreach (int number in numbers)
        {
            if (number > value)
            {
                count++;
            }
        }

        return count;
    }
}

Now:

List<int> numbers = new List<int>
{
    10, 20, 30, 40, 50
};

int result = numbers.CountGreaterThan(25);

Console.WriteLine(result);

Output:

3

Because:

30
40
50

are greater than 25.

17. Extension Methods and Polymorphism Are Different

Do not confuse extension methods with overriding.

Suppose:

Animal animal = new Dog();

animal.MakeSound();

If MakeSound() is virtual and overridden, runtime polymorphism determines which implementation runs.

Extension methods work differently.

They are resolved based on the compile-time type and available extension methods.

They do not participate in virtual dispatch.

So:

virtual/override
        ↓
runtime dispatch

extension method
        ↓
compile-time method resolution

This distinction is very important.

18. Extension Method Does Not Override Existing Behavior

You cannot use an extension method to override an existing method.

For example:

public static class MyExtensions
{
    public static string ToString(this Person person)
    {
        return "Custom";
    }
}

If Person already inherits ToString() from object, the extension method does not replace it.

The existing instance method has priority.

19. Extension Methods and null

Be careful here.

Consider:

public static class StringExtensions
{
    public static bool IsLongerThan(
        this string value,
        int length)
    {
        return value.Length > length;
    }
}

Then:

string text = null;

text.IsLongerThan(3);

The extension method itself can technically be called because it is really a static method:

StringExtensions.IsLongerThan(text, 3);

But inside:

value.Length

will cause a:

NullReferenceException

You can explicitly handle null:

public static bool IsLongerThan(
    this string? value,
    int length)
{
    if (value == null)
    {
        return false;
    }

    return value.Length > length;
}

Now:

string? text = null;

Console.WriteLine(text.IsLongerThan(3));

returns:

False

The important distinction is:

Can the extension method be called with null?
        ↓
Yes, because it is a static method.

Can its implementation safely handle null?
        ↓
Only if you design it to.
20. Extension Methods vs Normal Static Methods

Consider:

public static bool IsLongerThan(
    string value,
    int length)

Normal static call:

StringExtensions.IsLongerThan("Hello", 3);

Now add:

this
public static bool IsLongerThan(
    this string value,
    int length)

Now you get:

"Hello".IsLongerThan(3);

So the key difference is the this modifier on the first parameter.

Normal static method	Extension method
static	static
First parameter is normal	First parameter uses this
Called through class	Can be called through extended type
Helper.Do(value)	value.Do()
21. Extension Methods vs Inheritance

These solve different problems.

Inheritance

You control or can derive from the type:

class Dog : Animal
{
}

Relationship:

Dog IS-A Animal
Extension method

You don't modify the existing type:

public static bool IsLongerThan(
    this string value,
    int length)

Relationship:

String
   +
extra functionality

There is no new derived type.

22. Extension Methods vs Composition

Composition means:

Class A HAS-A Class B

For example:

class Car
{
    private Engine engine;
}

Extension methods are different.

They provide convenient additional behavior without storing an object relationship.

23. A More Realistic Example

Suppose you frequently need to check whether a collection contains elements.

You could repeatedly write:

if (numbers.Count > 0)
{
    // ...
}

You could create:

public static class CollectionExtensions
{
    public static bool HasItems<T>(
        this IEnumerable<T> collection)
    {
        return collection.Any();
    }
}

Now:

List<int> numbers = new List<int>
{
    10,
    20,
    30
};

if (numbers.HasItems())
{
    Console.WriteLine("Collection has items.");
}

This can make domain-specific code easier to read.

But there is an important design question:

Should every helper method become an extension method?

No.

Extension methods should be used when the method genuinely feels like behavior of the extended type.

24. Common Mistake: Putting Too Much Logic in Extensions

Bad design can look like:

public static class StringExtensions
{
    public static void DoEverything(
        this string value)
    {
        // 200 lines of unrelated logic
    }
}

The fact that something can be an extension method doesn't mean it should be one.

Good extension methods are usually:

focused
reusable
logically related to the extended type
easy to understand
reasonably small
25. Common Mistake: Forgetting the Namespace

You have:

namespace MyExtensions
{
    public static class StringExtensions
    {
        public static bool IsLongerThan(
            this string value,
            int length)
        {
            return value.Length > length;
        }
    }
}

But your consuming file doesn't have:

using MyExtensions;

Then:

"Hello".IsLongerThan(3);

may produce an error such as:

'string' does not contain a definition for 'IsLongerThan'

The extension exists, but the compiler cannot find it through the current namespace imports.

26. Common Mistake: Wrong First Parameter

Wrong:

public static bool IsLongerThan(
    string value,
    int length)

This is just a normal static method.

Correct:

public static bool IsLongerThan(
    this string value,
    int length)

The this is what marks the first parameter as the extended receiver.

27. Common Mistake: Thinking It Changes the Type

This:

"Hello".IsLongerThan(3);

does not mean that System.String was modified.

There is still no actual:

IsLongerThan()

method inside System.String.

The compiler translates the convenient syntax to a static method call.

Mental model:

Extension syntax

object.Method(argument)
        │
        ▼
ExtensionClass.Method(object, argument)
28. Important Limitation

Extension methods cannot:

access private members of the extended type
add actual instance fields
add actual instance properties
modify the original type's definition
override existing instance methods
participate in virtual dispatch

For example, if a class has:

private int secret;

your extension method cannot directly access:

obj.secret

because private still means private.

Extension methods follow normal access-control rules.

29. The Compiler Mental Model

When you write:

numbers.Where(x => x > 10);

you should mentally understand it as something like:

Enumerable.Where(
    numbers,
    x => x > 10
);

The exact generic signatures are more complex, but the important idea is:

numbers.Where(...)
        ↓
Extension method
        ↓
Enumerable.Where(numbers, ...)

This becomes extremely important when you start learning LINQ.

30. Complete Example
using System;
using System.Collections.Generic;
using System.Linq;

public static class StringExtensions
{
    public static bool IsLongerThan(
        this string value,
        int length)
    {
        return value.Length > length;
    }

    public static bool ContainsIgnoreCase(
        this string value,
        string searchText)
    {
        return value.Contains(
            searchText,
            StringComparison.OrdinalIgnoreCase);
    }
}

public static class CollectionExtensions
{
    public static bool HasItems<T>(
        this IEnumerable<T> collection)
    {
        return collection.Any();
    }
}

public class Program
{
    public static void Main()
    {
        string name = "Hariom";

        Console.WriteLine(
            name.IsLongerThan(3));

        Console.WriteLine(
            name.ContainsIgnoreCase("hari"));

        List<int> numbers = new List<int>
        {
            10,
            20,
            30
        };

        Console.WriteLine(
            numbers.HasItems());
    }
}

Output:

True
True
True

Notice how naturally the APIs read:

name.IsLongerThan(3);
name.ContainsIgnoreCase("hari");
numbers.HasItems();

You are about to start LINQ.

So understand this relationship now:

        │
        ├── Add method-like syntax

        ├── Work with existing types

34. What You Should Be Able to Explain

Before moving forward, you should be able to answer these without memorizing:

Q1. What is an extension method?

A static method that can be called using instance-style syntax on an existing type without modifying that type.

Q2. Why is this used?

It marks the first parameter as the type being extended.

Q3. Why must the method be static?

Extension methods are implemented as static methods; the instance-style syntax is compiler-supported syntax for calling that static method.

Q4. Does an extension method actually become part of the class?

No.

Q5. Which has priority?

An actual instance member has priority over an extension method.

Q6. Can an extension method override a virtual method?

No.

Q7. Why are extension methods important for LINQ?

Many LINQ operators such as Where, Select, and OrderBy are exposed through extension methods on IEnumerable<T>.
