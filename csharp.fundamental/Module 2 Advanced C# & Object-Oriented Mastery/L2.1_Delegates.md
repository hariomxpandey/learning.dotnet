Delegates in C#

Module 2.2 — Advanced Language Features

1. What Is a Delegate?

A delegate is a C# type that can hold a reference to a method.

In simple terms:

A delegate allows you to treat a method like a value and pass that method around.

Normally, we call a method directly:

PrintMessage();

With a delegate, we can store the method:

MessageDelegate del = PrintMessage;

and then invoke it:

del();

So the mental model is:

Method
   ↓
Delegate
   ↓
Store / Pass / Invoke
   ↓
Method executes
2. Why Do We Need Delegates?

Consider this:

static void PrintHello()
{
    Console.WriteLine("Hello");
}

static void PrintGoodbye()
{
    Console.WriteLine("Goodbye");
}

Without delegates, if another method needs to execute one of these methods, you might write separate logic:

static void ExecuteHello()
{
    PrintHello();
}

static void ExecuteGoodbye()
{
    PrintGoodbye();
}

This becomes rigid.

With a delegate, we can pass which method should execute:

static void Execute(MessageDelegate action)
{
    action();
}

Now:

Execute(PrintHello);
Execute(PrintGoodbye);

The same Execute() method can work with different methods.

That is one of the most important reasons delegates exist:

Delegates allow behavior to be passed as a parameter.

3. Delegate Syntax

A delegate is declared using the delegate keyword:

delegate void MessageDelegate();

Break it down:

delegate
   ↓
keyword

void
   ↓
return type

MessageDelegate
   ↓
delegate name

()
   ↓
parameter list

This delegate can reference methods having exactly this shape:

void MethodName()

For example:

static void PrintHello()
{
    Console.WriteLine("Hello");
}

This is compatible.

But:

static int Add()
{
    return 10;
}

is not compatible because the return type is different.

4. Delegate Type Is a Contract

This is extremely important.

When you declare:

delegate int Calculator(int a, int b);

you are defining a method signature contract.

Any compatible method must have:

return type → int
parameters   → int, int

For example:

static int Add(int a, int b)
{
    return a + b;
}

Compatible.

static int Multiply(int a, int b)
{
    return a * b;
}

Also compatible.

But:

static double Add(double a, double b)
{
    return a + b;
}

Not compatible.

The delegate does not care about the method's name.

It cares about the compatible signature.

5. Creating a Delegate Instance

Consider:

delegate void MessageDelegate();

static void PrintHello()
{
    Console.WriteLine("Hello");
}

We can create a delegate:

MessageDelegate del = PrintHello;

Then invoke it:

del();

Complete example:

using System;

class Program
{
    delegate void MessageDelegate();

    static void PrintHello()
    {
        Console.WriteLine("Hello");
    }

    static void Main()
    {
        MessageDelegate del = PrintHello;

        del();
    }
}

Output:

Hello
6. What Actually Happens?

This:

MessageDelegate del = PrintHello;

does not execute PrintHello().

It stores a reference to the method.

Execution happens here:

del();

Compare:

MessageDelegate del = PrintHello;

with:

PrintHello();

The first means:

"Store this method reference."

The second means:

"Execute this method now."

7. Delegate Invocation

Once a delegate contains a method:

MessageDelegate del = PrintHello;

you can invoke it:

del();

You can also use:

del.Invoke();

These are effectively two ways of invoking the delegate:

del();

and:

del.Invoke();

Usually:

del();

is preferred because it is cleaner.

8. Delegates With Parameters

Delegates can have parameters.

delegate void MessageDelegate(string message);

Now compatible methods must accept one string parameter:

static void PrintMessage(string message)
{
    Console.WriteLine(message);
}

Usage:

MessageDelegate del = PrintMessage;

del("Hello C#");

Output:

Hello C#
9. Delegates With Return Values

Delegates can also return values.

delegate int Calculator(int a, int b);

Compatible method:

static int Add(int a, int b)
{
    return a + b;
}

Usage:

Calculator calculator = Add;

int result = calculator(10, 20);

Console.WriteLine(result);

Output:

30

The delegate acts like a callable reference:

calculator(10, 20)
       ↓
      Add()
       ↓
     30
10. Passing a Delegate to a Method

This is where delegates become really powerful.

delegate int Calculator(int a, int b);

Now create a method that accepts the delegate:

static void Calculate(
    int a,
    int b,
    Calculator operation)
{
    int result = operation(a, b);

    Console.WriteLine(result);
}

We can pass different methods:

static int Add(int a, int b)
{
    return a + b;
}

static int Multiply(int a, int b)
{
    return a * b;
}

Then:

Calculate(10, 5, Add);
Calculate(10, 5, Multiply);

Output:

15
50

Notice something important.

We did not create two Calculate() methods.

The behavior was supplied from outside.

Calculate()
    |
    +---- Add
    |
    +---- Multiply

This is the core idea behind delegates.

11. Delegates Enable "Behavior as Data"

Normally we pass data:

Calculate(10, 20);

Here:

10 → data
20 → data

With delegates, we can also pass behavior:

Calculate(10, 20, Add);

Now:

10       → data
20       → data
Add      → behavior

This concept is fundamental to many advanced C# features.

12. Delegate and Method Signature

Suppose:

delegate int Operation(int x, int y);

These methods are compatible:

static int Add(int x, int y)
{
    return x + y;
}
static int Subtract(int x, int y)
{
    return x - y;
}
static int Multiply(int x, int y)
{
    return x * y;
}

But this is not:

static int Add(int x)
{
    return x;
}

because the parameter list doesn't match.

And this is not:

static double Add(int x, int y)
{
    return x + y;
}

because the return type doesn't match the delegate contract.

13. Static Methods and Instance Methods

A delegate can reference both static and instance methods.

Static method
delegate void Printer(string text);

static void Print(string text)
{
    Console.WriteLine(text);
}

Printer printer = Print;
Instance method
class PrinterService
{
    public void Print(string text)
    {
        Console.WriteLine(text);
    }
}

Then:

PrinterService service = new PrinterService();

Printer printer = service.Print;

printer("Hello");

The delegate can therefore reference behavior belonging to an object as well.

14. Delegate Object and Target Method

Conceptually, a delegate contains information about:

Delegate
├── Method
└── Target

For a static method:

Printer printer = Print;

there is no particular object instance required.

For an instance method:

Printer printer = service.Print;

the delegate maintains the connection to the target object:

printer
   |
   +---- service object
            |
            +---- Print()

This is why an instance method can later be invoked through the delegate.

15. Delegates Are Type-Safe

Delegates are strongly typed.

Given:

delegate int Operation(int x, int y);

you cannot accidentally assign an incompatible method:

Operation op = PrintMessage; // Compile-time error

if:

static void PrintMessage(string message)
{
    Console.WriteLine(message);
}

The compiler checks compatibility.

This is much safer than loosely storing method information and trying to invoke it dynamically.

16. Multicast Delegates

A delegate can reference multiple methods.

This is called a multicast delegate.

Suppose:

delegate void Notification();

Methods:

static void SendEmail()
{
    Console.WriteLine("Email sent");
}

static void SendSms()
{
    Console.WriteLine("SMS sent");
}

We can combine them:

Notification notification = SendEmail;

notification += SendSms;

Now:

notification();

Output:

Email sent
SMS sent

The methods execute in the invocation list.

Conceptually:

notification
     |
     +---- SendEmail()
     |
     +---- SendSms()
17. Adding and Removing Methods

Use:

+=

to add a method.

notification += SendEmail;
notification += SendSms;

Use:

-=

to remove a method.

notification -= SendEmail;

Then only:

SendSms()

remains in the invocation list.

18. Important Multicast Delegate Detail

Consider:

delegate void Operation();

and:

Operation operation = Method1;

operation += Method2;
operation += Method3;

Invocation:

operation();

executes:

Method1
Method2
Method3

in invocation-list order.

But multicast delegates have an important limitation:

The return value is not useful for collecting results from every method.

For example:

delegate int Calculator();

If multiple methods are attached:

calculator += Method1;
calculator += Method2;

the delegate invocation ultimately returns the result from the last invoked method.

Therefore multicast delegates are commonly used with void-returning methods.

19. Exceptions in Multicast Delegates

Suppose:

operation += Method1;
operation += Method2;
operation += Method3;

If Method2() throws an exception during normal delegate invocation:

operation();

execution does not simply continue normally to Method3().

The exception propagates out of the invocation unless handled.

This matters when using delegates as event-like notification mechanisms.

20. Delegate Assignment vs Invocation

This distinction is very important.

Assignment
Calculator calc = Add;

You are storing the method.

Invocation
calc(10, 20);

You are executing the referenced method.

Passing
Execute(Add);

You are passing the method reference to another method.

Think:

Add
 ↓
store
 ↓
delegate
 ↓
pass
 ↓
invoke
 ↓
execute
21. Delegate as a Method Parameter

This pattern is extremely important:

static void Execute(Operation operation)
{
    operation();
}

Now:

Execute(Method1);
Execute(Method2);
Execute(Method3);

The Execute() method does not need to know the exact implementation.

It only knows:

"Give me something that matches the Operation delegate contract."

This is an early form of dependency injection through behavior.

22. A Realistic Example

Imagine an application processing payments.

delegate void PaymentProcessor(decimal amount);

Different payment methods:

static void PayByCard(decimal amount)
{
    Console.WriteLine($"Card payment: {amount}");
}

static void PayByUPI(decimal amount)
{
    Console.WriteLine($"UPI payment: {amount}");
}

Generic processing method:

static void ProcessPayment(
    decimal amount,
    PaymentProcessor processor)
{
    processor(amount);
}

Now:

ProcessPayment(500, PayByCard);
ProcessPayment(500, PayByUPI);

The processing method doesn't need separate implementations for every payment type.

The behavior is supplied through the delegate.

23. Delegate vs Direct Method Call
Direct method call
ProcessPayment(500);

The method itself decides what implementation runs.

Delegate-based
ProcessPayment(500, PayByCard);

The caller supplies the behavior.

This gives us greater flexibility.

24. Delegate vs Interface

You have already learned interfaces, so this distinction is important.

An interface usually represents a capability or object contract:

interface IPayment
{
    void Pay(decimal amount);
}

A delegate represents a callable behavior/method signature:

delegate void PaymentProcessor(decimal amount);
Interface
IPayment payment = new CreditCardPayment();

payment.Pay(500);

The object implements a contract.

Delegate
PaymentProcessor processor = PayByCard;

processor(500);

The delegate directly represents callable behavior.

A useful mental model:

Interface
   ↓
"What can this object do?"

Delegate
   ↓
"Which method/behavior should I execute?"
25. Delegate vs Inheritance

Inheritance creates a type relationship:

Dog IS-A Animal

Delegates don't establish an inheritance relationship between behaviors.

Instead:

Execute()
   |
   +---- Add()
   +---- Multiply()
   +---- Divide()

The method receives behavior dynamically.

26. Anonymous Methods

C# also allows creating a method-like body directly for a delegate.

Example:

delegate void MessageDelegate(string message);

MessageDelegate del = delegate(string message)
{
    Console.WriteLine(message);
};

del("Hello");

This is called an anonymous method.

There is no separately named method such as:

static void Print(string message)

Instead, the implementation is written directly where the delegate is assigned.

27. Why Anonymous Methods Matter

Without anonymous methods:

static void PrintMessage(string message)
{
    Console.WriteLine(message);
}

MessageDelegate del = PrintMessage;

With an anonymous method:

MessageDelegate del = delegate(string message)
{
    Console.WriteLine(message);
};

The second form is useful when the behavior is small and only needed locally.

However, modern C# code usually uses lambda expressions for this purpose.

You will study lambdas next.

28. Anonymous Method Can Capture Variables

Consider:

int number = 10;

Action action = delegate
{
    Console.WriteLine(number);
};

action();

The anonymous method can access the variable from its surrounding scope.

This concept is called a closure.

The same concept becomes much more important with lambda expressions.

29. Delegate Creation Can Be Simplified

You can write:

Calculator calculator = new Calculator(Add);

This explicitly creates the delegate.

But C# allows simpler syntax:

Calculator calculator = Add;

The compiler understands that Add must be converted to the compatible delegate type.

So these represent the same basic idea:

Calculator calculator = new Calculator(Add);

and:

Calculator calculator = Add;

The second is the normal modern syntax.

30. Delegate Type vs Delegate Instance

Don't confuse these two.

Delegate type
delegate int Calculator(int a, int b);

This defines the type.

Delegate instance
Calculator calc = Add;

This creates a value of that delegate type.

Similar to:

class Person
{
}

and:

Person person = new Person();

Conceptually:

delegate declaration
       ↓
defines a type

delegate variable
       ↓
holds a method reference
31. Null Delegates

A delegate variable can be null:

Calculator calc = null;

Trying to invoke it:

calc(10, 20);

causes:

NullReferenceException

You can safely check:

if (calc != null)
{
    calc(10, 20);
}

Modern C# also supports:

calc?.Invoke(10, 20);

This means:

Invoke the delegate only if it is not null.

32. Generic Delegates Preview

C# provides built-in generic delegate types such as:

Func<>
Action<>
Predicate<>

These are extremely important because you often don't need to declare your own delegate type.

For example:

Func<int, int, int>

means:

two int parameters
        ↓
one int return value

So instead of:

delegate int Calculator(int a, int b);

you can use:

Func<int, int, int> calculator;

We will study Func, Action, and Predicate separately in depth.

34. Delegate as a Callback

A callback means:

Give another piece of code a method to call later.

Example:

delegate void Callback();

static void Finished()
{
    Console.WriteLine("Operation finished.");
}

static void DoWork(Callback callback)
{
    Console.WriteLine("Working...");

    callback();
}

Usage:

DoWork(Finished);

Output:

Working...
Operation finished.

Conceptually:

Caller
  |
  | gives Finished()
  ↓
DoWork()
  |
  | does work
  ↓
callback()
  |
  ↓
Finished()

Callbacks become especially useful in asynchronous programming and event-driven systems.

You will see this connection again in async, Task, and events.

35. Complete Example
using System;

class Program
{
    delegate int Operation(int a, int b);

    static int Add(int a, int b)
    {
        return a + b;
    }

    static int Multiply(int a, int b)
    {
        return a * b;
    }

    static void Execute(
        int a,
        int b,
        Operation operation)
    {
        int result = operation(a, b);

        Console.WriteLine($"Result: {result}");
    }

    static void Main()
    {
        Execute(10, 5, Add);
        Execute(10, 5, Multiply);
    }
}

Output:

Result: 15
Result: 50

The important architecture is:

                Execute()
                   |
          +--------+--------+
          |                 |
        Add()          Multiply()
          |                 |
          +--------+--------+
                   |
              Operation
               delegate
36. The Deep Mental Model

Think of a delegate as a strongly typed function reference.

For:

delegate int Operation(int x, int y);

you are saying:

"I want something callable that accepts two int values and produces an int."

Then:

Operation operation = Add;

means:

"Use Add as that callable behavior."

Then:

operation(10, 20);

means:

"Execute whichever compatible method this delegate currently represents."

This is the key idea you should remember.

37. Important Distinctions
Concept	Meaning
Method	Contains executable behavior
Delegate type	Defines the shape of callable behavior
Delegate instance	Holds reference to compatible method(s)
Delegate invocation	Executes referenced method(s)
Multicast delegate	Delegate containing multiple methods
Callback	Method passed so another method can invoke it later
Anonymous method	Inline unnamed method body
Lambda	Compact syntax for function-like behavior
38. Common Mistakes
Mistake 1 — Invoking while assigning

Wrong:

Calculator calc = Add(10, 20);

Add() returns an int, not a Calculator.

Correct:

Calculator calc = Add;

Then:

int result = calc(10, 20);
Mistake 2 — Signature mismatch
delegate int Calculator(int a, int b);

static double Add(double a, double b)
{
    return a + b;
}

This is not compatible.

Mistake 3 — Forgetting that a delegate can be null
Calculator calc = null;

calc(10, 20);

This can throw NullReferenceException.

Mistake 4 — Thinking delegate means method execution
Calculator calc = Add;

does not execute Add.

Only:

calc(10, 20);

executes it.

39. Delegate Flow

Remember this flow:

1. Define delegate
       ↓
2. Find compatible method
       ↓
3. Assign method to delegate
       ↓
4. Pass delegate if needed
       ↓
5. Invoke delegate
       ↓
6. Referenced method executes

Example:

delegate int Operation(int x, int y);

↓

static int Add(int x, int y)
{
    return x + y;
}

↓

Operation operation = Add;

↓

Execute(operation);

↓

operation(10, 20);

↓

Add(10, 20)

↓

30
