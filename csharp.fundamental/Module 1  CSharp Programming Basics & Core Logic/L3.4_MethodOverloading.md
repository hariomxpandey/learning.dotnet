Method Overloading

Module: 1 — C# Programming Basics & Core Logic
Section: 1.3 Methods & Code Structure
Prerequisite: Methods, parameters, return types, ref, out, params, scope

1. What Is Method Overloading?

Method overloading means:

Multiple methods can have the same name but different parameter lists.

Example:

static int Add(int a, int b)
{
    return a + b;
}

static int Add(int a, int b, int c)
{
    return a + b + c;
}

Both methods are named:

Add

But their parameters are different.

Add(int, int)
Add(int, int, int)

Therefore, C# can distinguish them.

2. Why Do We Need Overloading?

Without overloading, you might create different names for essentially the same operation:

AddTwoNumbers(10, 20);
AddThreeNumbers(10, 20, 30);
AddFourNumbers(10, 20, 30, 40);

This becomes unnecessarily complicated.

With overloading:

Add(10, 20);

Add(10, 20, 30);

Add(10, 20, 30, 40);

Same operation concept:

Add
 ↓
different input forms
3. Basic Example
static void Print()
{
    Console.WriteLine("Hello");
}

static void Print(string name)
{
    Console.WriteLine("Hello " + name);
}

Now:

Print();

calls:

Print()

While:

Print("Hariom");

calls:

Print(string)

The compiler determines which method you mean based on the arguments.

4. The Key Rule

Two methods can have the same name if their parameter lists are different.

For example:

Add(int, int)
Add(int, int, int)

are different signatures.

But:

Add(int, int)
Add(int, int)

are exactly the same signature and cannot coexist.

5. Different Number of Parameters

This is the simplest form of overloading.

static int Multiply(int a, int b)
{
    return a * b;
}

static int Multiply(int a, int b, int c)
{
    return a * b * c;
}

Usage:

Console.WriteLine(Multiply(2, 3));
Console.WriteLine(Multiply(2, 3, 4));

Output:

6
24
6. Different Parameter Types

Methods can also be overloaded using different parameter types.

static void Print(int value)
{
    Console.WriteLine("Integer: " + value);
}

static void Print(string value)
{
    Console.WriteLine("String: " + value);
}

Now:

Print(10);

calls:

Print(int)

And:

Print("Hello");

calls:

Print(string)
7. Same Number of Parameters, Different Types

This is also valid:

static int Add(int a, int b)
{
    return a + b;
}

static double Add(double a, double b)
{
    return a + b;
}

The parameter lists are:

Add(int, int)
Add(double, double)

Different types → valid overloads.

8. Parameter Order Can Matter

Consider:

static void Display(int number, string text)
{
    Console.WriteLine(number + " " + text);
}

static void Display(string text, int number)
{
    Console.WriteLine(text + " " + number);
}

These are different parameter lists:

Display(int, string)
Display(string, int)

So both can exist.

Calling:

Display(10, "Hello");

selects:

Display(int, string)

Calling:

Display("Hello", 10);

selects:

Display(string, int)
9. Method Signature

This is important for understanding overloading.

For methods, the signature includes the:

Method name
Number of parameters
Parameter types
Parameter modifiers such as ref, in, and out where applicable

Conceptually:

MethodName + parameter list

Example:

Add(int, int)

and:

Add(double, double)

have different signatures.

10. Return Type Alone Cannot Overload a Method

This is a very important rule.

You cannot do this:

static int GetValue()
{
    return 10;
}

static double GetValue()
{
    return 10.5;
}

This is invalid.

Why?

Because both methods have the same parameter list:

GetValue()
GetValue()

The return type is different, but return type alone does not create an overload.

11. Why Return Type Is Not Enough

Imagine:

int x = GetValue();

and:

double x = GetValue();

If C# allowed overloading only by return type, the compiler would have to determine the method from the expected return type.

C# does not use return type alone to distinguish ordinary method overloads.

Therefore:

Different return type
        ≠
Different overload
12. Parameters Matter

Valid:

static int GetValue(int x)
{
    return x;
}

static double GetValue(double x)
{
    return x;
}

Why?

Because:

GetValue(int)
GetValue(double)

have different parameter types.

13. Overloading vs params

Consider:

static int Add(int a, int b)
{
    return a + b;
}

static int Add(params int[] numbers)
{
    int total = 0;

    foreach (int number in numbers)
    {
        total += number;
    }

    return total;
}

This can compile, but calls can involve overload resolution between the fixed-parameter overload and the params overload.

For example:

Add(10, 20);

The normal fixed-parameter overload is generally preferred because it is a more direct match.

This is one reason to avoid unnecessary overlapping overloads.

14. Overloading With ref

ref participates in distinguishing method signatures.

For example:

static void Process(int value)
{
    Console.WriteLine("Normal");
}

static void Process(ref int value)
{
    Console.WriteLine("Ref");
}

These have different parameter forms:

Process(int)
Process(ref int)

Call:

int number = 10;

Process(number);
Process(ref number);

The calls select different overloads.

15. ref Must Match at the Call Site

If the method is:

static void Process(ref int value)
{
}

then:

Process(ref number);

is required.

You cannot call it as:

Process(number);

The compiler uses the argument form as part of overload resolution.

16. out and Overloading

out also participates in method signatures in relevant overload scenarios.

Example:

static void GetValue(out int value)
{
    value = 10;
}

The caller must use:

int number;

GetValue(out number);

The out modifier is part of the method's parameter specification.

17. ref vs out Overloads

A subtle point:

You should not design methods simply to create confusing overloads such as:

static void Test(ref int x)
{
}

static void Test(out int x)
{
    x = 10;
}

Although ref and out are distinct parameter modifiers in C#, calls become harder to reason about, and API design should prioritize clarity.

In normal application code, use ref and out because they serve a clear purpose, not merely to create overloads.

18. Compiler Chooses the Best Match

This is called overload resolution.

Suppose:

static void Print(int value)
{
    Console.WriteLine("int");
}

static void Print(double value)
{
    Console.WriteLine("double");
}

Now:

Print(10);

The argument is an int.

So C# chooses:

Print(int)

because it is the better match.

19. Exact Match vs Conversion

Consider:

static void Print(long value)
{
    Console.WriteLine("long");
}

static void Print(double value)
{
    Console.WriteLine("double");
}

Then:

int number = 10;

Print(number);

An int can implicitly convert to both long and double.

This can create situations where overload resolution needs to determine which conversion is better.

The important lesson for now:

Don't create overload sets that make calls ambiguous or difficult to understand.

20. Ambiguous Overload

Consider:

static void Print(long value)
{
}

static void Print(double value)
{
}

Now:

Print(10);

Depending on the available conversions and overload set, the compiler may not have a uniquely best overload.

When the compiler cannot determine the best method, you get an ambiguous call compiler error.

This is why overload design matters.

21. Constructor Overloading

Method overloading isn't limited to ordinary methods.

Constructors can also be overloaded.

Example:

class Student
{
    public Student()
    {
        Console.WriteLine("Default constructor");
    }

    public Student(string name)
    {
        Console.WriteLine("Name constructor");
    }

    public Student(string name, int age)
    {
        Console.WriteLine("Name + age constructor");
    }
}

Now:

Student s1 = new Student();

Student s2 = new Student("Hariom");

Student s3 = new Student("Hariom", 22);

Each call selects a different constructor.

We'll go much deeper into constructors in the OOP section.

22. Method Overloading Is Compile-Time Polymorphism

Method overloading is commonly described as:

Compile-time polymorphism

Why?

Because the compiler determines which overloaded method should be called during compilation based on the available method signatures and argument types.

For example:

Print(10);

The compiler resolves this against the available overloads.

This is different from runtime polymorphism, which we'll study later with:

virtual
override
inheritance
23. Overloading vs Overriding

Don't confuse these two.

Overloading

Same class:

same method name
different parameters

Example:

Add(int, int)
Add(int, int, int)
Overriding

Inheritance:

base class method
      ↓
derived class replaces behavior

Example:

virtual
override

We'll study overriding in Module 2.1.

24. Overloading Example From Real APIs

You frequently see overloaded methods in .NET.

For example, methods may accept:

string
string + formatting information
different parameter combinations

The goal is convenience:

same conceptual operation
        ↓
different input forms

Instead of forcing every caller to use one complicated signature.

25. When Should You Use Overloading?

Use overloading when:

1. The operation is conceptually the same

Good:

Add(10, 20);
Add(10, 20, 30);

Both mean:

addition
2. Inputs naturally vary

Example:

Print(string text)
Print(string text, int count)
3. The overloads remain easy to understand

Good APIs should be predictable.

26. When Should You Avoid Overloading?

Avoid overloads when they create confusion.

For example, if you have:

Process(int)
Process(long)
Process(double)
Process(decimal)
Process(float)

and conversions make calls unclear, users may struggle to understand which method is selected.

Sometimes a different method name is clearer.

For example:

ProcessInteger()
ProcessDecimal()

The correct choice depends on the API design.

27. Overloading and Optional Parameters

Be careful when combining:

overloading
+
optional parameters

Example:

static void Print(string text)
{
}

static void Print(string text, int count = 1)
{
}

Now:

Print("Hello");

can match both methods.

This can create an ambiguous call.

Therefore:

Don't create overlapping overloads and optional parameters without a clear reason.

28. Overloading With Named Arguments

Consider:

static void Display(string name, int age)
{
}

static void Display(int age, string name)
{
}

You can call:

Display(name: "Hariom", age: 22);

This selects the overload whose parameter names/types fit that invocation.

But named arguments do not remove the fundamental requirement that the call must match a valid overload.

29. Overload Resolution — Simple Mental Model

When you call:

Add(10, 20);

think of the compiler doing something conceptually like:

Find methods named Add
        ↓
Check their parameters
        ↓
Can the arguments fit?
        ↓
Rank the possible matches
        ↓
Choose the best match
        ↓
Compile the call

You don't manually perform these steps every time, but understanding them explains many compiler errors.

30. Example: Overload Resolution
static void Print(int number)
{
    Console.WriteLine("int");
}

static void Print(string text)
{
    Console.WriteLine("string");
}

static void Print(double number)
{
    Console.WriteLine("double");
}

Calls:

Print(10);
Print("Hello");
Print(10.5);

Results:

int
string
double

The argument type gives the compiler a strong match.

31. Example With Variables
int a = 10;
double b = 20.5;
string c = "Hello";

Print(a);
Print(b);
Print(c);

The compile-time types are:

a → int
b → double
c → string

So the corresponding overloads are selected.

32. Overloading Does Not Depend on Variable Names

These are different:

static void Add(int a, int b)
{
}

static void Add(int x, int y)
{
}

But this is not valid.

Why?

Because parameter names don't matter for overload identity.

Both have:

Add(int, int)

Changing:

a → x
b → y

doesn't create a new overload.

33. Parameter Names vs Parameter Types

This is important.

Names:
Add(int a, int b)
Add(int x, int y)

Same signature.

Types:
Add(int a, int b)
Add(double a, double b)

Different signatures.

Therefore:

parameter names → don't create overloads
parameter types → can create overloads
34. Return Type vs Parameter Types

Remember:

static int Calculate(int x)
{
    return x;
}

and:

static double Calculate(int x)
{
    return x;
}

Not valid as overloads.

But:

static int Calculate(int x)
{
    return x;
}

static double Calculate(double x)
{
    return x;
}

is valid.

The difference is in the parameter type.

35. Overloading and params

Consider:

static void Test(int x)
{
    Console.WriteLine("Normal");
}

static void Test(params int[] values)
{
    Console.WriteLine("Params");
}

Call:

Test(10);

The fixed parameter overload is a more direct match:

Test(int)

than the params form.

So the normal overload is preferred.

Again, avoid designing confusing overload sets unless there is a real need.

36. Common Mistakes
Mistake 1 — Trying to Overload Only by Return Type
static int GetNumber()
{
    return 10;
}

static double GetNumber()
{
    return 10.5;
}

❌ Invalid.

Mistake 2 — Changing Only Parameter Names
static void Print(int x)
{
}

static void Print(int y)
{
}

❌ Invalid.

Mistake 3 — Creating Confusing Overloads

Too many similar conversions can make calls ambiguous or difficult to predict.

Prefer simple and meaningful overload sets.

Mistake 4 — Confusing Overloading With Overriding
overloading → same class / method name / different parameters

overriding → inheritance / virtual / override

They are different concepts.

37. Complete Example
class Calculator
{
    public int Add(int a, int b)
    {
        return a + b;
    }

    public int Add(int a, int b, int c)
    {
        return a + b + c;
    }

    public double Add(double a, double b)
    {
        return a + b;
    }
}

Usage:

Calculator calculator = new Calculator();

int result1 = calculator.Add(10, 20);

int result2 = calculator.Add(10, 20, 30);

double result3 = calculator.Add(10.5, 20.5);

The same conceptual operation:

Add

supports different input forms.

38. Deep Understanding

The purpose of overloading isn't:

"Create many methods with the same name."

The real purpose is:

Represent the same operation cleanly for different parameter combinations.

Think:

                  Add
                   │
        ┌──────────┼──────────┐
        ↓          ↓          ↓
    int,int    int,int,int  double,double

One concept.

Multiple valid input shapes.
