Classes and Objects

Module: 1 — C# Programming Basics & Core Logic
Section: 1.4 Core Object-Oriented Programming
Prerequisite: Methods, parameters, scope, method overloading

1. Why Do We Need Classes and Objects?

So far, we have worked mainly with:

int age = 22;
string name = "Hariom";
double salary = 50000;

This works for small programs.

But imagine we need to represent a student.

A student may have:

Name
Age
Roll Number
Course
Marks

And a student can perform actions:

Study()
AttendClass()
TakeExam()
DisplayDetails()

If we keep everything as separate variables and methods, the program becomes difficult to organize.

OOP gives us a way to group related data + behavior together.

Student
│
├── Data
│   ├── Name
│   ├── Age
│   └── RollNumber
│
└── Behavior
    ├── Study()
    ├── AttendClass()
    └── DisplayDetails()

The main building blocks are:

Class
  ↓
Object
2. What Is a Class?

A class is a blueprint or definition used to create objects.

Example:

class Student
{
    public string Name;
    public int Age;

    public void Study()
    {
        Console.WriteLine("Student is studying.");
    }
}

Here:

Student

is a class.

It describes what a student object should contain.

Think of a class as a design/template.

Class = Blueprint
3. What Is an Object?

An object is an actual instance of a class.

Example:

Student student1 = new Student();

Here:

Student

is the class/type.

student1

is the object/reference variable.

new Student()

creates an object.

Conceptually:

Class
 Student
   │
   │ creates
   ↓
Object
 student1
4. Class vs Object

This distinction is extremely important.

Class

A class defines what an object will have.

class Student
{
    public string Name;
    public int Age;
}
Object

An object is an actual instance.

Student student1 = new Student();

Think:

Class
  ↓
Blueprint

Object
  ↓
Actual thing created from blueprint
5. Real-World Analogy

Imagine a house blueprint.

House Blueprint
├── Rooms
├── Doors
├── Windows
└── Kitchen

The blueprint isn't an actual house.

You can use the blueprint to construct multiple houses:

Blueprint
   │
   ├── House 1
   ├── House 2
   └── House 3

Similarly:

Student class
     │
     ├── student1
     ├── student2
     └── student3

One class can create many objects.

7. Creating an Object

Suppose we have:

class Student
{
    public string Name;
    public int Age;
}

Create an object:

Student student1 = new Student();

Break it down:

Student student1 = new Student();
   │       │           │
   │       │           └── Creates object
   │       └────────────── Reference variable
   └────────────────────── Type
8. Understanding new

This is important.

new Student()

means:

Create a new instance of Student.

Example:

Student student1 = new Student();
Student student2 = new Student();

Now there are two separate objects.

Conceptually:

student1 ──→ Student object
student2 ──→ Student object

They are separate instances.

9. Assigning Field Values

Given:

class Student
{
    public string Name;
    public int Age;
}

We can do:

Student student1 = new Student();

student1.Name = "Hariom";
student1.Age = 22;

Now:

student1
│
├── Name → "Hariom"
└── Age  → 22
10. Reading Object Data

We can access the fields using the dot operator:

Console.WriteLine(student1.Name);
Console.WriteLine(student1.Age);

The . means:

Access a member of this object.

Example:

student1.Name

means:

student1
   ↓
access Name
11. Object Behavior With Methods

Classes can contain methods.

class Student
{
    public string Name;

    public void Study()
    {
        Console.WriteLine(Name + " is studying.");
    }
}

Create an object:

Student student1 = new Student();

student1.Name = "Hariom";

student1.Study();

Output:

Hariom is studying.

Now data and behavior are grouped together.

12. Data + Behavior

This is one of the most important OOP ideas.

Instead of:

Student data
+
random methods somewhere else

we can group them:

Student
│
├── Name
├── Age
│
└── Study()

So:

Class = Data + Behavior

More precisely, a class can encapsulate data and behavior that belong together.

13. Multiple Objects

One class can create many objects.

class Student
{
    public string Name;
    public int Age;
}

Now:

Student student1 = new Student();
Student student2 = new Student();
Student student3 = new Student();

Set their values:

student1.Name = "Hariom";
student1.Age = 22;

student2.Name = "Aman";
student2.Age = 21;

student3.Name = "Rahul";
student3.Age = 23;

Conceptually:

Student class
      │
      ├── student1
      │   ├── Name = Hariom
      │   └── Age = 22
      │
      ├── student2
      │   ├── Name = Aman
      │   └── Age = 21
      │
      └── student3
          ├── Name = Rahul
          └── Age = 23

Same structure.

Different data.

14. Objects Have Their Own State

This is a fundamental concept.

student1.Age = 22;
student2.Age = 30;

Changing student1 doesn't normally change student2.

Why?

Because they are separate object instances.

student1
Age = 22

student2
Age = 30

Each object has its own instance state.

15. Instance Members

A field declared inside a class without static is normally an instance field.

Example:

class Student
{
    public string Name;
    public int Age;
}

Name and Age belong to each object.

Therefore:

student1.Name
student2.Name

can contain different values.

16. Instance Method

A method without static is an instance method.

class Student
{
    public string Name;

    public void Study()
    {
        Console.WriteLine(Name + " is studying.");
    }
}

You need an object to call it:

Student student = new Student();

student.Name = "Hariom";

student.Study();

This connects directly to the earlier topic of static.

static method
   ↓
class-level access

instance method
   ↓
object-level access
17. Instance Method Can Access Instance Data

Example:

class Student
{
    public string Name;

    public void Introduce()
    {
        Console.WriteLine("My name is " + Name);
    }
}

Notice that Introduce() doesn't receive Name as a parameter.

It can access the object's instance field:

Name

because the method is being executed for a particular object.

student1.Introduce()
       ↓
uses student1.Name

student2.Introduce()
       ↓
uses student2.Name
18. Example
class Student
{
    public string Name;

    public void Introduce()
    {
        Console.WriteLine("My name is " + Name);
    }
}

class Program
{
    static void Main()
    {
        Student student1 = new Student();
        Student student2 = new Student();

        student1.Name = "Hariom";
        student2.Name = "Aman";

        student1.Introduce();
        student2.Introduce();
    }
}

Output:

My name is Hariom
My name is Aman

Same method.

Different objects.

Different state.

19. What Actually Happens Conceptually?

When you write:

Student student1 = new Student();

think:

Student
   │
   ↓
new object created
   │
   ↓
student1 refers to that object

Then:

student1.Name = "Hariom";

means:

Find object referred to by student1
        ↓
Access its Name field
        ↓
Store "Hariom"
20. Reference Variable vs Object

This is a deeper but important distinction.

Consider:

Student student1 = new Student();

There are conceptually two things:

student1

and:

Student object

student1 is a reference variable.

new Student() creates the object.

Think:

student1 ─────────→ [Student object]

The variable holds a reference to the object.

21. Two References Can Point to One Object

Consider:

Student student1 = new Student();

student1.Name = "Hariom";

Student student2 = student1;

Now:

student1 ─────┐
              ↓
        [Student object]
              ↑
student2 ─────┘

Both references refer to the same object.

Therefore:

student2.Name = "Aman";

Console.WriteLine(student1.Name);

prints:

Aman

Because student1 and student2 refer to the same object.

This reference behavior will become very important later.

22. Creating Two Separate Objects

Compare:

Student student1 = new Student();
Student student2 = new Student();

Now:

student1 ──→ [Object A]

student2 ──→ [Object B]

These are separate objects.

Changing one does not directly change the other's instance fields.

1500

Here the class represents a real-world concept.

Good:

Naming conventions don't usually affect whether code compiles, but they strongly affect readability and maintainability.

Without OOP, a large application might become:

variables everywhere

data relationships unclear

With classes:

Student

Order

This makes it easier to:

organize code

The later OOP topics build on this foundation.

31. Class Does Not Mean Real-World Object Only

Classes don't have to represent physical things.

You can create classes for abstract concepts:

Logger
DatabaseConnection
OrderProcessor
FileManager
EmailService
Calculator

For example:

class Calculator
{
    public int Add(int a, int b)
    {
        return a + b;
    }
}

So don't limit your understanding of classes to physical objects like:

Car
Dog
Student

A class can model any concept that benefits from grouping related state and behavior.

33. The Four Words You Must Know

35. Mini Project Example

Let's combine everything we've learned so far.

class Student
{
    public string Name;
    public int Age;

    {

        Console.WriteLine("Age: " + Age);
        Console.WriteLine("Marks: " + Marks);

    {
        Console.WriteLine(Name + " is studying.");

class Program

37. Common Beginner Confusions
Confusion 1

Is a class an object?

No.

Class  → definition
Object → instance
Confusion 2

Does declaring a class create an object?

No.

class Student
{
}

only defines the type.

Confusion 3

Does new Student() create the reference variable?

No.

In:

Student student = new Student();

student is the reference variable, while new Student() creates the object.

Confusion 4

Can one class have multiple objects?

Yes.

Student s1 = new Student();
Student s2 = new Student();
Student s3 = new Student();
Confusion 5

Do all objects have the same values?

No.

They have the same structure, but instance data can differ.

s1 → Name = Hariom
s2 → Name = Aman
38. Important Distinction: Structure vs State

Suppose:

class Student
{
    public string Name;
    public int Age;
}

Every Student object has the structure:

Name
Age

But state can differ:

Student 1
Name = Hariom
Age = 22

Student 2
Name = Aman
Age = 21

So:

Class → defines structure

Object → contains a particular state
