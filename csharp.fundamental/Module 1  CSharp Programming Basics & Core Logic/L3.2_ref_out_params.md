ref, out, and params in C#

Module: 1 — C# Programming Basics & Core Logic
Section: 1.3 Methods & Code Structure
Prerequisite: Methods, parameters, arguments, return values

1. Why Do We Need ref, out, and params?

So far, we learned normal parameters:

static int Add(int a, int b)
{
    return a + b;
}

When calling:

int x = 10;
int y = 20;

int result = Add(x, y);

the method receives values of x and y.

x = 10 ──→ a = 10
y = 20 ──→ b = 20

But sometimes we need different behavior:

Normal parameter
→ method receives a value

ref
→ method can read and modify caller's variable

out
→ method must produce a value for caller

params
→ method can receive variable number of arguments

These three keywords solve different problems.

2. First Understand Normal Parameters

Before ref, understand the normal case.

static void Change(int number)
{
    number = 100;
}

Caller:

int x = 10;

Change(x);

Console.WriteLine(x);

Output:

10

Why?

Because:

Caller:

x = 10

      value copied
          ↓
Method:

number = 10

Then:

number = 100

changes the method's local parameter, not the caller's x.

3. ref

ref allows a method to work with the same variable supplied by the caller.

Example:

static void Change(ref int number)
{
    number = 100;
}

Call:

int x = 10;

Change(ref x);

Console.WriteLine(x);

Output:

100

Now the flow is different:

x
│
│ ref
↓
number
│
│ number = 100
↓
x = 100
4. The ref Keyword

Syntax:

static void Method(ref int number)
{
    number = 100;
}

And when calling:

Method(ref x);

Notice:

ref is required in both places.

Method declaration
ref int number
Method call
ref x

You cannot normally write:

Method(x);

when the method expects ref.

5. ref Requires Initialization

This is important.

Before calling a ref parameter, the variable must already have a value.

Correct:

int x = 10;

Change(ref x);

Incorrect:

int x;

Change(ref x);

Why?

Because ref means the method can both:

read
+
modify

the existing variable.

So C# requires the caller to initialize it first.

6. ref Can Read the Existing Value

Example:

static void Increase(ref int number)
{
    number = number + 10;
}

Caller:

int x = 20;

Increase(ref x);

Console.WriteLine(x);

Output:

30

Flow:

x = 20
 ↓
Increase(ref x)
 ↓
number = 20
 ↓
number + 10
 ↓
30
 ↓
x = 30
7. ref Is Useful When You Need to Modify the Caller

Example:

static void Double(ref int number)
{
    number *= 2;
}

Call:

int value = 5;

Double(ref value);

Console.WriteLine(value);

Output:

10

Without ref, the original variable would remain 5.

8. ref With Strings

ref can also be used with reference types such as string.

static void ChangeName(ref string name)
{
    name = "Hariom";
}

Call:

string name = "Aman";

ChangeName(ref name);

Console.WriteLine(name);

Output:

Hariom
9. ref Mental Model

Think:

Normal parameter

x = 10
  ↓ copy
number = 10

number = 100

x = 10

With ref:

x = 10
  ↓ same variable
number
  ↓
number = 100

x = 100

The important distinction is:

normal → value passed
ref    → variable passed by reference
10. out

Now let's look at out.

out is used when the method is responsible for producing a value through a parameter.

Example:

static void GetNumber(out int number)
{
    number = 100;
}

Call:

int x;

GetNumber(out x);

Console.WriteLine(x);

Output:

100

Notice something important:

int x;

doesn't initialize x.

That's allowed with out.

11. Why Does out Not Require Initialization?

Because out means:

"The method promises to assign a value before it finishes."

Example:

static void GetValue(out int number)
{
    number = 50;
}

The method must assign:

number = 50;

before returning.

Therefore:

int x;

GetValue(out x);

is valid.

Flow:

x
│
│ out
↓
method
│
│ produces 50
↓
x = 50
12. out Must Be Assigned

This is invalid:

static void GetValue(out int number)
{
}

Why?

Because the method promises to provide an output value.

It must assign:

number = something;

before returning.

Correct:

static void GetValue(out int number)
{
    number = 100;
}
13. out Is Commonly Used for Multiple Outputs

Normally a method returns one value:

static int Add(int a, int b)
{
    return a + b;
}

But sometimes we want to produce multiple results.

Example:

static void Calculate(int a, int b, out int sum, out int difference)
{
    sum = a + b;
    difference = a - b;
}

Call:

int sum;
int difference;

Calculate(20, 5, out sum, out difference);

Console.WriteLine(sum);
Console.WriteLine(difference);

Output:

25
15

Flow:

20, 5
  ↓
Calculate()
  ├── sum = 25
  └── difference = 15
14. out With TryParse

One of the most important real-world examples is:

int.TryParse()

Example:

string input = "123";

bool success = int.TryParse(input, out int number);

Now:

success → true
number  → 123

If the input is invalid:

string input = "abc";

bool success = int.TryParse(input, out int number);

Then:

success → false

The important idea is:

TryParse()
     ↓
Did conversion succeed?
     ↓
bool

What value was produced?
     ↓
out parameter
15. out Variable Declaration During Call

Modern C# allows:

int.TryParse("123", out int number);

instead of:

int number;

int.TryParse("123", out number);

The variable is declared directly in the argument list.

16. ref vs out

This is extremely important.

Feature	ref	out
Caller must initialize variable	Yes	No
Method can read parameter	Yes	Yes, after assigning it
Method can modify parameter	Yes	Yes
Method must assign before return	No	Yes
ref/out required at call	Yes	Yes
Main purpose	Modify existing value	Produce output value

Mental model:

ref
→ "Here is an existing value. Work with it."

out
→ "I don't have a value yet. You produce one."
17. Example: ref vs out
ref
static void AddTen(ref int number)
{
    number += 10;
}

Caller:

int x = 20;

AddTen(ref x);

x already had a value.

20 → method → 30
out
static void GetTen(out int number)
{
    number = 10;
}

Caller:

int x;

GetTen(out x);

x didn't need a value before the call.

nothing → method → 10
18. params

Now the third keyword.

Sometimes we don't know how many arguments a method will receive.

For example:

Add(10, 20);

What if we want:

Add(10, 20, 30);

or:

Add(10, 20, 30, 40, 50);

Instead of creating many overloads, we can use params.

19. Basic params
static int Add(params int[] numbers)
{
    int total = 0;

    foreach (int number in numbers)
    {
        total += number;
    }

    return total;
}

Now we can call:

Console.WriteLine(Add(10, 20));

Output:

30

Or:

Console.WriteLine(Add(10, 20, 30));

Output:

60

Or:

Console.WriteLine(Add(10, 20, 30, 40, 50));

Output:

150
20. What Does params Actually Do?

Look at:

static int Add(params int[] numbers)

The parameter is actually:

int[]

So inside the method:

numbers

is an array.

For:

Add(10, 20, 30);

C# effectively gives the method a collection of those values.

Conceptually:

Add(10, 20, 30)
       ↓
numbers
       ↓
[10, 20, 30]

Therefore you can use:

foreach

or:

numbers.Length

or indexing:

numbers[0]
21. params Can Accept Zero Arguments

Example:

static int Add(params int[] numbers)
{
    int total = 0;

    foreach (int number in numbers)
    {
        total += number;
    }

    return total;
}

This is valid:

Console.WriteLine(Add());

Result:

0

The params array can contain zero elements.

22. params Can Also Accept an Array

You can call:

int[] values = { 10, 20, 30 };

Console.WriteLine(Add(values));

This works because:

params int[]

expects an array of int.

So params gives you convenient syntax for passing individual arguments while still working with an array inside the method.

23. Rules for params

A params parameter:

Must be an array type
Allows variable number of arguments
Can receive zero or more arguments
Must be the last parameter

Correct:

static void Print(string name, params int[] numbers)
{
}

Incorrect:

static void Print(params int[] numbers, string name)
{
}

The params parameter must come last.

24. params With Other Parameters

Example:

static void PrintNumbers(string title, params int[] numbers)
{
    Console.WriteLine(title);

    foreach (int number in numbers)
    {
        Console.WriteLine(number);
    }
}

Call:

PrintNumbers("Numbers", 10, 20, 30);

Output:

Numbers
10
20
30

Flow:

"Numbers"
    ↓
title

10, 20, 30
    ↓
numbers[]
25. ref, out, and params Comparison

Think of them as three different jobs:

             Method Parameters
                    │
       ┌────────────┼────────────┐
       ↓            ↓            ↓
      ref          out         params
       │            │            │
       ↓            ↓            ↓
Existing       Produce       Many
variable       a value       arguments
       │            │            │
       ↓            ↓            ↓
Modify it      Output it     Collect them
26. A Real Example Using All Three

You can technically use all three in one method:

static void Process(
    ref int counter,
    out int total,
    params int[] numbers)
{
    counter++;

    total = 0;

    foreach (int number in numbers)
    {
        total += number;
    }
}

Call:

int counter = 0;
int total;

Process(ref counter, out total, 10, 20, 30);

Console.WriteLine(counter);
Console.WriteLine(total);

Output:

1
60

But don't use all three together just because you can.

Good code uses these features when they make the method's contract clearer.

27. Important: Normal Return vs out

Often, you don't need out.

For one result, prefer a normal return:

static int Add(int a, int b)
{
    return a + b;
}

Instead of:

static void Add(int a, int b, out int result)
{
    result = a + b;
}

The first is simpler:

Add()
 ↓
return result

out becomes useful when the API naturally needs multiple outputs or follows a pattern such as TryParse.

28. ref Should Also Be Used Intentionally

Don't use:

ref

just because you want to change something.

If returning a new value is clearer:

static int Double(int number)
{
    return number * 2;
}

is often preferable to:

static void Double(ref int number)
{
    number *= 2;
}

Compare:

int result = Double(number);

with:

Double(ref number);

The first makes the data flow explicit:

input → output

The second mutates the caller's variable.

29. ref Changes the Caller

This is the biggest thing to remember.

static void Increment(ref int value)
{
    value++;
}

Then:

int number = 10;

Increment(ref number);

After the call:

number = 11

The caller's variable has changed.

Therefore, when reading code containing ref, always ask:

"Is this method going to mutate my variable?"

30. out Produces Data

When you see:

GetData(out result);

think:

result is being filled by the method

Example:

int result;

GetData(out result);

After the method completes:

result → value produced by GetData()
31. params Collects Data

When you see:

Add(10, 20, 30, 40);

and the method is:

static int Add(params int[] numbers)

think:

10
20
30
40
 ↓
numbers[]

Then the method can process the array.

32. Common Mistakes
Mistake 1 — Forgetting ref at the Call

Method:

static void Change(ref int x)
{
    x = 100;
}

Incorrect:

Change(x);

Correct:

Change(ref x);
Mistake 2 — Using Uninitialized Variable With ref

Incorrect:

int x;

Change(ref x);

Correct:

int x = 10;

Change(ref x);
Mistake 3 — Not Assigning an out Parameter

Incorrect:

static void GetValue(out int value)
{
}

Correct:

static void GetValue(out int value)
{
    value = 100;
}
Mistake 4 — Putting params Somewhere Other Than Last

Incorrect:

static void Test(params int[] numbers, string name)
{
}

Correct:

static void Test(string name, params int[] numbers)
{
}
33. The Most Important Mental Model

Memorize the concept, not the syntax:

Normal
→ Give method a value.

ref
→ Give method access to an existing variable.

out
→ Ask method to provide a value.

params
→ Give method any number of arguments.

Or even shorter:

normal → value in
ref    → existing variable
out    → value out
params → many values in
34. Practice
Practice 1 — ref

Create:

Increase(ref int number)

It should increase the caller's number by 10.

Example:

number = 20

Increase(ref number)

number = 30
Practice 2 — ref

Create:

Swap(ref int a, ref int b)

Example:

a = 10
b = 20

Swap(ref a, ref b)

a = 20
b = 10

Do not use a third method or built-in swap function.

Practice 3 — out

Create:

GetMinMax(int a, int b, out int min, out int max)

Example:

GetMinMax(10, 30, out min, out max)

min = 10
max = 30
Practice 4 — out

Create:

GetFullName(
    string firstName,
    string lastName,
    out string fullName)

Example:

GetFullName("Hariom", "Kumar", out fullName)

fullName = "Hariom Kumar"
Practice 5 — params

Create:

Sum(params int[] numbers)

Examples:

Sum(10, 20)
→ 30

Sum(10, 20, 30)
→ 60

Sum(1, 2, 3, 4, 5)
→ 15
Practice 6 — params

Create:

FindMaximum(params int[] numbers)

Example:

FindMaximum(10, 50, 20, 40)
→ 50

Do not use Math.Max().
