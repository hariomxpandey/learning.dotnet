Lesson 30 — C# ArrayList

Part: 5 — Collections & Errors
Topic: ArrayList
Prerequisite: List<T> and Dictionary<TKey, TValue>

1. What Is ArrayList?

ArrayList is an older non-generic collection in C#.

Namespace:

using System.Collections;

Example:

ArrayList numbers = new ArrayList();

numbers.Add(10);
numbers.Add(20);
numbers.Add(30);

Conceptually:

ArrayList
   ↓
[10][20][30]

It can store different types:

ArrayList data = new ArrayList();

data.Add(10);
data.Add("Hello");
data.Add(3.14);
data.Add(true);

So:

int
string
double
bool

can all exist in the same ArrayList.

This is one of the major differences from:

List<int>
2. Why Can ArrayList Store Different Types?

The important concept is:

ArrayList
   ↓
object

Historically, ArrayList stores elements as object.

Since every C# type ultimately derives from object in the type system, different values can be placed into it.

Conceptually:

10
 ↓
object

"Hello"
 ↓
object

3.14
 ↓
object

This flexibility comes at a cost.

3. ArrayList vs List<T>

Compare:

List<int> numbers = new List<int>();

with:

ArrayList numbers = new ArrayList();
List<int>
Only int
   ↓
10 ✓
20 ✓
"Hello" ✗
ArrayList
object
   ↓
10 ✓
20 ✓
"Hello" ✓
3.14 ✓

Therefore:

List<T> provides compile-time type safety, while ArrayList does not.

4. Basic ArrayList Example
using System;
using System.Collections;

class Program
{
    static void Main()
    {
        ArrayList numbers = new ArrayList();

        numbers.Add(10);
        numbers.Add(20);
        numbers.Add(30);

        Console.WriteLine(numbers[0]);
    }
}

Output:

10

It supports indexing similar to arrays and List<T>.

5. Add()
ArrayList data = new ArrayList();

data.Add(10);
data.Add("Hello");
data.Add(true);

Result conceptually:

[10]["Hello"][true]

Each element is treated through the object type.

6. Count

Like List<T>:

Console.WriteLine(data.Count);

If there are three elements:

3

So:

Array
    → Length

List<T>
    → Count

ArrayList
    → Count
7. Indexing
ArrayList data = new ArrayList();

data.Add("A");
data.Add("B");
data.Add("C");

Console.WriteLine(data[1]);

Output:

B

Indexes still begin at 0.

0 → A
1 → B
2 → C
8. Updating an Element

You can change an existing element:

data[1] = "X";

Before:

[A][B][C]

After:

[A][X][C]

But remember: the values are handled as object.

9. Insert()
ArrayList numbers = new ArrayList();

numbers.Add(10);
numbers.Add(30);

numbers.Insert(1, 20);

Result:

[10][20][30]

Same basic idea as List<T>.

10. Remove()
ArrayList numbers = new ArrayList();

numbers.Add(10);
numbers.Add(20);
numbers.Add(30);

numbers.Remove(20);

Result:

[10][30]

It removes the first matching value.

11. RemoveAt()

Remove using an index:

numbers.RemoveAt(0);

Before:

[10][30]

After:

[30]
12. Clear()

Remove everything:

numbers.Clear();

Now:

Count = 0
13. Contains()

Check whether an element exists:

ArrayList numbers = new ArrayList
{
    10,
    20,
    30
};

bool exists = numbers.Contains(20);

Result:

true
14. IndexOf()
int index = numbers.IndexOf(20);

If 20 is at index 1:

1

If it doesn't exist:

-1
15. Iterating an ArrayList

You can use:

foreach (object item in data)
{
    Console.WriteLine(item);
}

Why object?

Because ArrayList doesn't guarantee a specific element type.

It can contain:

int
string
double
bool
Student
...

So the common type is:

object
16. The Big Problem — Type Safety

Consider:

ArrayList data = new ArrayList();

data.Add(10);
data.Add(20);
data.Add("Hello");

Now suppose you assume everything is an integer:

foreach (object item in data)
{
    int number = (int)item;
    Console.WriteLine(number);
}

The first two work:

10 → int ✓
20 → int ✓

But:

"Hello" → int ✗

This causes:

InvalidCastException

The compiler didn't protect you because ArrayList accepts object.

17. Compare With List<int>

With:

List<int> numbers = new List<int>();

this:

numbers.Add(10);
numbers.Add(20);

works.

But:

numbers.Add("Hello");

is rejected by the compiler.

That's a major advantage of generics.

List<int>
   ↓
Compiler knows:
"Only int belongs here."

Whereas:

ArrayList
   ↓
Compiler knows:
"Elements are object."
18. Boxing

Now we reach an important C# concept.

Consider:

int number = 10;

object value = number;

This is called boxing.

Conceptually:

int
 ↓
boxing
 ↓
object

For value types such as int, the value is wrapped in an object representation.

ArrayList commonly involves boxing when you add value types.

Example:

ArrayList numbers = new ArrayList();

numbers.Add(10);

Conceptually:

int 10
   ↓
boxing
   ↓
object
   ↓
ArrayList
19. Unboxing

The reverse operation is called unboxing.

object value = 10;

int number = (int)value;

Conceptually:

object containing int
       ↓
   unboxing
       ↓
      int

This is different from a normal reference-type cast.

The type being unboxed must be compatible with the actual boxed value.

20. Boxing + ArrayList

Consider:

ArrayList numbers = new ArrayList();

numbers.Add(10);

Because 10 is an int value type, it is boxed to be stored through object.

Later:

int number = (int)numbers[0];

The value is unboxed.

So the conceptual flow is:

10
 ↓
boxing
 ↓
object
 ↓
ArrayList
 ↓
numbers[0]
 ↓
unboxing
 ↓
int

This is one reason generic collections were introduced as a better approach for many scenarios.

21. Why Boxing Can Matter

Suppose you have many value types:

ArrayList numbers = new ArrayList();

numbers.Add(10);
numbers.Add(20);
numbers.Add(30);

Each value type may need to be boxed.

Then when retrieved:

int x = (int)numbers[0];

it needs to be unboxed.

This can introduce:

additional allocations
additional work
casts
reduced type safety

Modern generic collections can avoid much of this for value-type collections.

22. List<int> vs ArrayList

Compare:

List<int> numbers = new List<int>();

numbers.Add(10);

int x = numbers[0];

There is no need to manually cast the element.

The compiler already knows:

numbers[0]
    ↓
int

With:

ArrayList numbers = new ArrayList();

numbers.Add(10);

int x = (int)numbers[0];

you need a cast.

So:

List<int>
    ↓
strongly typed

ArrayList
    ↓
object-based
23. Why ArrayList Still Exists

You might wonder:

If List<T> is better in most modern code, why does ArrayList exist?

Because it is part of the older .NET collection APIs and remains available for:

legacy applications
older APIs
compatibility with existing code

Modern C# development generally prefers generic collections such as:

List<T>
Dictionary<TKey, TValue>
HashSet<T>
Queue<T>
Stack<T>

when their semantics fit the problem.

24. ArrayList Is Non-Generic

This distinction is important.

Generic
List<int>

The type is specified.

Non-generic
ArrayList

The collection operates through object.

Therefore:

Generic
   ↓
compile-time type information

Non-generic
   ↓
object-based storage
25. ArrayList With Mixed Types

This is technically possible:

ArrayList data = new ArrayList();

data.Add(10);
data.Add("Hello");
data.Add(3.14);
data.Add(true);

You could then inspect types:

foreach (object item in data)
{
    Console.WriteLine(item.GetType());
}

Conceptually:

System.Int32
System.String
System.Double
System.Boolean

But just because something is possible doesn't mean it is good design.

A collection containing unrelated types often makes code harder to reason about.

26. ArrayList vs List<T> — Full Comparison
Feature	ArrayList	List<T>
Generic	❌	✅
Type-safe	❌	✅
Stores through	object	T
Mixed types	Possible	Not normally
Boxing value types	Can occur	Avoided for T value types
Casting on retrieval	Often required	Usually not
Modern C# preference	Usually no	Usually yes
Namespace	System.Collections	System.Collections.Generic
27. Performance Mental Model

Consider:

ArrayList data = new ArrayList();

For an int:

int
 ↓
boxing
 ↓
object
 ↓
store

When retrieving:

object
 ↓
cast/unbox
 ↓
int

With:

List<int>

the collection is strongly typed:

int
 ↓
List<int>

So generic collections can avoid the boxing/unboxing overhead associated with storing value types through object.

28. Important: Generic Does Not Mean "Always Faster"

Don't reduce the lesson to:

Generic = fast
Non-generic = slow

The more important advantages of generics are:

Type safety
+
Less casting
+
Better compile-time checking
+
Avoidance of unnecessary boxing for value types

Performance depends on the actual workload and implementation.

29. ArrayList and Reference Types

If you store a reference type:

class Student
{
    public string Name { get; set; }
}

then:

ArrayList students = new ArrayList();

students.Add(new Student
{
    Name = "Hariom"
});

The reference itself can be stored through object.

The boxing issue primarily concerns value types, such as:

int
double
bool
struct
30. Practical Example
using System;
using System.Collections;

class Program
{
    static void Main()
    {
        ArrayList data = new ArrayList();

        data.Add(10);
        data.Add(20);
        data.Add("Hello");

        Console.WriteLine($"Count: {data.Count}");

        foreach (object item in data)
        {
            Console.WriteLine(item);
        }

        int firstNumber = (int)data[0];

        Console.WriteLine($"First number: {firstNumber}");
    }
}

Output:

Count: 3
10
20
Hello
First number: 10

Notice the cast:

(int)data[0]

That is necessary because data[0] is exposed as object.

31. A Dangerous Example
ArrayList data = new ArrayList();

data.Add(10);
data.Add("Hello");

int number = (int)data[1];

At runtime:

"Hello"
   ↓
cannot become int
   ↓
InvalidCastException

The compiler cannot catch this specific mistake because ArrayList allows both values.

With:

List<int>

the mistake is rejected much earlier.

32. The Real Reason List<T> Is Preferred

Imagine a large application.

With ArrayList:

object
 ↓
cast
 ↓
possible InvalidCastException

With:

List<Student>

you get:

Student
 ↓
compiler knows the type
 ↓
less casting
 ↓
safer code

Generic collections move many errors from runtime to compile time.

That's a major improvement in software design.

Remember:

    ↓

    ↓

List<T>

34. Key Takeaways
1. ArrayList is a non-generic collection.

2. It belongs to System.Collections.

3. ArrayList stores elements through object.

4. It can contain different types.

5. It supports Add(), Insert(), Remove(), RemoveAt(),
   Contains(), IndexOf(), Clear(), Count, etc.

6. Because values are exposed through object, casting is
   often required when retrieving them.

7. Value types stored through object can involve boxing.

8. Retrieving them back can involve unboxing.

9. Incorrect casts can cause InvalidCastException.

10. List<T> provides compile-time type safety.

11. List<T> generally avoids the boxing/unboxing overhead
    associated with storing value types through object.

12. Modern C# code generally prefers generic collections
    over ArrayList when possible.

13. ArrayList mainly remains relevant for legacy/compatibility
    scenarios.
