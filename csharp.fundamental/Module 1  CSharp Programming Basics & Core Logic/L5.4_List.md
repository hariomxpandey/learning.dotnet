Lesson 28 — C# List<T>

Part: 5 — Collections & Errors
Topic: List<T>
Prerequisite: Arrays

1. Why Do We Need List<T>?

You already know arrays:

int[] numbers = new int[5];

An array has a fixed length.

Once created:

5 elements
  ↓
[10][20][30][40][50]

you cannot make that same array become 6 elements.

But many real programs need collections whose size changes:

Add item
Remove item
Add another item
Remove another item
...

That's where:

List<T>

comes in.

2. What Is List<T>?

List<T> is a generic collection that stores multiple values of a specified type.

Example:

List<int> numbers = new List<int>();

Here:

List<int>
    ↑
    T = int

So this list can contain only int values.

numbers.Add(10);
numbers.Add(20);
numbers.Add(30);

Conceptually:

numbers
   ↓
[10][20][30]

Unlike an array, the list can grow.

3. Namespace

List<T> belongs to:

System.Collections.Generic

Usually:

using System.Collections.Generic;

Example:

using System;
using System.Collections.Generic;

class Program
{
    static void Main()
    {
        List<int> numbers = new List<int>();

        numbers.Add(10);
        numbers.Add(20);

        Console.WriteLine(numbers.Count);
    }
}

Output:

2
4. Understanding <T>

The T in:

List<T>

means:

The type of element stored in the list.

Examples:

List<int> numbers;
List<string> names;
List<double> prices;
List<bool> flags;

Conceptually:

List<int>
   ↓
int values

List<string>
   ↓
string values

List<double>
   ↓
double values
5. Why Is List<T> Generic?

Consider:

List<int> numbers = new List<int>();

The compiler knows that this list contains int.

Therefore:

numbers.Add(10);

is valid.

But:

numbers.Add("Hello");

is invalid.

This gives you:

type safety
compile-time checking
no need to manually cast every element
cleaner code
6. Creating a List
Empty List
List<int> numbers = new List<int>();

Initially:

numbers
   ↓
[]

Then:

numbers.Add(10);

becomes:

[10]

Then:

numbers.Add(20);

becomes:

[10][20]
7. Collection Initializer

You can create and initialize a list directly:

List<int> numbers = new List<int>
{
    10,
    20,
    30,
    40
};

Modern C# also supports:

List<int> numbers = new()
{
    10,
    20,
    30,
    40
};

The type is already known from the left side:

List<int>

so the compiler can infer the constructor type.

8. Add()

The most basic operation:

List<string> names = new List<string>();

names.Add("Hariom");
names.Add("Rahul");
names.Add("Aman");

Result:

[Hariom][Rahul][Aman]

Each Add() puts an element at the end.

9. Order Is Preserved

Consider:

List<int> numbers = new List<int>();

numbers.Add(30);
numbers.Add(10);
numbers.Add(20);

The list contains:

[30][10][20]

It does not automatically sort itself.

If you want sorting:

numbers.Sort();

Now:

[10][20][30]
10. Accessing Elements

Like arrays, lists use indexes.

List<string> names = new List<string>
{
    "A",
    "B",
    "C"
};

Access:

Console.WriteLine(names[0]);

Output:

A

And:

Console.WriteLine(names[2]);

Output:

C

So:

Index
  0 → A
  1 → B
  2 → C
11. Updating an Element

You can modify an element using its index:

names[1] = "Rahul";

Before:

[A][B][C]

After:

[A][Rahul][C]

This is similar to arrays.

12. Count

Use:

numbers.Count

to get the current number of elements.

Example:

List<int> numbers = new List<int>
{
    10,
    20,
    30
};

Console.WriteLine(numbers.Count);

Output:

3

Important:

Array:
Length

List<T>:
Count
13. Count vs Capacity

This is an important distinction.

A List<T> internally maintains storage capacity.

Example:

List<int> numbers = new List<int>();

Conceptually:

Count = 0
Capacity = some available storage

After:

numbers.Add(10);
numbers.Add(20);
numbers.Add(30);

you have:

Count = 3

But:

Capacity

may be larger than 3.

Therefore:

Count = actual number of elements.

Capacity = amount of internal storage currently allocated.

Never use Capacity when you want to know how many elements are in the list.

Use:

numbers.Count
14. Why Does List<T> Need Capacity?

Suppose a list had to allocate a completely new storage area every time you did:

Add()

That would be inefficient.

Instead, List<T> maintains internal storage with some capacity.

When the current storage becomes insufficient, it grows its internal storage.

Conceptually:

Initial
Capacity = X

Add elements
     ↓
Capacity becomes full
     ↓
Allocate larger storage
     ↓
Copy existing elements
     ↓
Continue

The exact growth strategy is an implementation detail and should not be relied upon as a fixed constant.

The important concept is:

List<T> dynamically resizes its internal storage when necessary.

15. Add() and Dynamic Growth

Example:

List<int> numbers = new List<int>();

numbers.Add(10);
numbers.Add(20);
numbers.Add(30);
numbers.Add(40);

From the programmer's perspective:

[10][20][30][40]

You don't need to manually create a larger array.

List<T> handles the resizing internally.

16. AddRange()

Suppose you want to add several values:

List<int> numbers = new List<int>
{
    1,
    2
};

You could do:

numbers.Add(3);
numbers.Add(4);
numbers.Add(5);

Or:

numbers.AddRange(new int[] { 3, 4, 5 });

Now:

[1][2][3][4][5]

You can also use another collection:

List<int> extra = new List<int>
{
    6,
    7,
    8
};

numbers.AddRange(extra);
17. Insert()

Add() adds at the end.

Insert() lets you specify the position.

List<string> names = new List<string>
{
    "A",
    "C"
};

names.Insert(1, "B");

Before:

[A][C]

After:

[A][B][C]

The existing elements are shifted to make room.

18. Insert() and Indexes

Example:

List<int> numbers = new List<int>
{
    10,
    20,
    30
};

numbers.Insert(0, 5);

Result:

[5][10][20][30]

Everything after index 0 shifts right.

This is important for performance when working with large lists.

19. Remove()

Remove() removes the first matching element.

List<int> numbers = new List<int>
{
    10,
    20,
    30,
    20
};

numbers.Remove(20);

Result:

[10][30][20]

Only the first 20 is removed.

20. RemoveAt()

RemoveAt() removes an element using its index.

List<int> numbers = new List<int>
{
    10,
    20,
    30
};

numbers.RemoveAt(1);

Result:

[10][30]

Because index 1 contained:

20
21. RemoveRange()

You can remove multiple consecutive elements:

List<int> numbers = new List<int>
{
    10,
    20,
    30,
    40,
    50
};

numbers.RemoveRange(1, 2);

The arguments mean:

starting index = 1
number of elements = 2

So:

[10][20][30][40][50]
     ↑   ↑
   remove

Result:

[10][40][50]
22. Clear()

Remove all elements:

numbers.Clear();

Before:

[10][20][30]

After:

[]

Important:

Count → 0

But Clear() does not necessarily mean that the internal capacity is immediately returned to zero.

Again:

Count

and:

Capacity

are different concepts.

23. Contains()

Check whether an element exists:

List<int> numbers = new List<int>
{
    10,
    20,
    30
};

bool exists = numbers.Contains(20);

Result:

true

And:

numbers.Contains(50);

returns:

false
24. IndexOf()

Find the index of an element:

List<string> names = new List<string>
{
    "Aman",
    "Rahul",
    "Hariom"
};

int index = names.IndexOf("Hariom");

Result:

2

If the item doesn't exist:

names.IndexOf("Unknown");

returns:

-1

So:

0 or greater → found
-1            → not found
25. LastIndexOf()

If an element appears multiple times:

List<int> numbers = new List<int>
{
    10,
    20,
    10,
    30,
    10
};

Then:

numbers.IndexOf(10);

returns:

0

while:

numbers.LastIndexOf(10);

returns:

4
26. Iterating a List
foreach
List<int> numbers = new List<int>
{
    10,
    20,
    30
};

foreach (int number in numbers)
{
    Console.WriteLine(number);
}

This is usually the cleanest option when you only need values.

27. for With a List

You can also use indexes:

for (int i = 0; i < numbers.Count; i++)
{
    Console.WriteLine(numbers[i]);
}

Notice:

numbers.Count

instead of:

numbers.Length
28. List<T> Is Mutable

Consider:

List<int> numbers = new List<int>
{
    10,
    20,
    30
};

You can:

numbers.Add(40);
numbers[0] = 99;
numbers.Remove(20);

So the list's contents can change after creation.

29. List of Objects

List<T> becomes especially powerful with classes.

Suppose:

class Student
{
    public string Name { get; set; }
    public int Age { get; set; }
}

Now:

List<Student> students = new List<Student>();

Add objects:

students.Add(new Student
{
    Name = "Hariom",
    Age = 21
});

students.Add(new Student
{
    Name = "Rahul",
    Age = 22
});

Conceptually:

students
   ↓
┌──────────────┐
│ Student      │
│ Name=Hariom  │
│ Age=21       │
└──────────────┘

┌──────────────┐
│ Student      │
│ Name=Rahul   │
│ Age=22       │
└──────────────┘

This pattern is extremely common in real C# applications.

30. Why Generics Matter Here

Without generics, a collection could hold arbitrary object values.

For example, older collection APIs could allow:

int
string
double
Student
...

all in the same collection.

That creates problems:

No strong type safety
       ↓
Runtime casting
       ↓
Possible invalid casts
       ↓
More errors

With:

List<Student>

the compiler knows:

This list is intended to contain Student objects.

That is one of the major benefits of generic collections.

31. List<T> vs Array
Feature	Array	List<T>
Size	Fixed	Dynamic
Indexing	Yes	Yes
Length	Yes	No
Count	No	Yes
Add()	No	Yes
Remove()	No	Yes
Insert()	No	Yes
Sort()	Array.Sort()	List.Sort()
Type-safe	Yes	Yes
Generic	No	Yes
Dynamic resizing	No	Yes
32. When Should You Use an Array?

Use an array when:

The size is known/fixed
        AND
you mainly need indexed storage

Example:

int[] months = new int[12];

There are always 12 positions.

33. When Should You Use List<T>?

Use List<T> when:

The number of elements can change
        OR
you need convenient collection operations

Example:

List<string> tasks = new List<string>();

tasks.Add("Study");
tasks.Add("Practice");
tasks.Add("Build project");

The number of tasks can change dynamically.

34. A Common Mistake

Don't do this unnecessarily:

List<int> numbers = new List<int>();

numbers.Add(10);
numbers.Add(20);
numbers.Add(30);

int[] array = numbers.ToArray();

There is nothing inherently wrong with it.

But don't convert back and forth without a reason.

Choose the collection type according to what the program needs.

35. Important: List<T> Is Not a Linked List

The name can be misleading.

List<T> is implemented as a dynamic array, not as a linked list.

Conceptually:

List<T>
   ↓
internal array
   ↓
dynamic resizing

This explains why:

Index access
    ↓
fast / efficient

while inserting/removing near the beginning can require shifting elements.

You should not assume:

List<T> = linked list

It isn't.

.NET also has a separate:

LinkedList<T>

type.

36. Performance Mental Model

Think approximately like this:

Operation	Typical behavior
list[i]	Fast
Add() at end	Usually fast
RemoveAt(0)	Can be expensive
Insert(0, value)	Can be expensive
Contains()	Searches elements
IndexOf()	Searches elements
Sort()	Performs sorting

Why is inserting at the beginning potentially expensive?

Suppose:

[A][B][C][D]

Insert X at index 0:

[X][A][B][C][D]

Existing elements need to move.

37. Capacity

You can inspect capacity:

List<int> numbers = new List<int>();

Console.WriteLine(numbers.Count);
Console.WriteLine(numbers.Capacity);

These represent different things.

Example conceptually:

Count     = 3
Capacity = 4

means:

3 actual elements
4 slots available internally

The exact capacity values can change as the .NET implementation evolves.

Do not write application logic that assumes a specific growth factor.

38. Setting Initial Capacity

If you know approximately how many elements you'll add, you can provide an initial capacity:

List<int> numbers = new List<int>(1000);

This means:

Initial capacity ≈ 1000

It does not mean:

Count = 1000

Immediately after creation:

Count = 0
Capacity = 1000

Conceptually.

This can reduce repeated resizing when you know the expected size.

39. TrimExcess()

A list can have more capacity than it currently needs.

There is:

numbers.TrimExcess();

which can reduce excess capacity.

But don't call it after every removal.

Frequent resizing/shrinking can itself be inefficient.

Use it only when there is a real memory-management reason.

40. Complete Example
using System;
using System.Collections.Generic;

class Program
{
    static void Main()
    {
        List<string> students = new List<string>();

        students.Add("Hariom");
        students.Add("Rahul");
        students.Add("Aman");

        Console.WriteLine($"Count: {students.Count}");

        students.Insert(1, "Ravi");

        Console.WriteLine("Students:");

        foreach (string student in students)
        {
            Console.WriteLine(student);
        }

        Console.WriteLine();

        if (students.Contains("Hariom"))
        {
            Console.WriteLine("Hariom exists.");
        }

        int index = students.IndexOf("Aman");

        Console.WriteLine($"Aman index: {index}");

        students.Remove("Rahul");

        Console.WriteLine($"Count after removal: {students.Count}");
    }
}
41. Mental Model

Keep this picture in your mind:

                List<T>
                   │
                   ▼
          Dynamic collection
                   │
        ┌──────────┴──────────┐
        ▼                     ▼
     Count                 Capacity
actual elements        internal storage
        │
        ▼
   [A][B][C][D]
     │  │  │
     └──┴──┴── indexed access

Main operations:

Add()          → end
AddRange()     → multiple at end
Insert()       → specific index
Remove()       → first matching value
RemoveAt()     → specific index
RemoveRange()  → multiple by range
Clear()        → all elements
Contains()     → existence
IndexOf()      → find first index
Count          → number of elements
42. Key Takeaways
1. List<T> is a generic collection.

2. T represents the element type.

3. List<T> has dynamic size.

4. List<T> provides index-based access.

5. Count tells you how many elements exist.

6. Capacity tells you how much internal storage is allocated.

7. Add() adds to the end.

8. Insert() adds at a specific index.

9. Remove() removes the first matching value.

10. RemoveAt() removes by index.

11. AddRange() adds multiple elements.

12. Clear() removes all elements.

13. Contains() checks existence.

14. IndexOf() finds an element's index.

15. List<T> is internally based on a dynamic array.

16. List<T> is not a linked list.

17. List<T> is generally preferable to old non-generic
    collection types when you need a strongly typed dynamic collection.
