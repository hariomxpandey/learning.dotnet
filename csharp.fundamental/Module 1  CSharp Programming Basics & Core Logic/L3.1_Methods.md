Methods in C#

Module: 1 — C# Programming Basics & Core Logic

Prerequisite: Variables, conditions, loops, arrays, strings

1. What Is a Method?

A method is a named block of code that performs a specific task.

Instead of writing the same logic repeatedly:

Console.WriteLine("Hello");
Console.WriteLine("Hello");
Console.WriteLine("Hello");

we can put the logic inside a method:

static void SayHello()
{
    Console.WriteLine("Hello");
}

Then call it:

SayHello();
SayHello();
SayHello();

Output:

Hello
Hello
Hello
2. Why Do We Need Methods?

Methods help us:

Reuse code
Break large problems into smaller pieces
Make code easier to read
Make code easier to test
Avoid unnecessary repetition
Organize program logic

Without methods:

Main()
 ├── 100 lines
 ├── 200 lines
 ├── 300 lines
 └── difficult to understand

With methods:

Main()
 ├── GetUserInput()
 ├── CalculateTotal()
 ├── ValidateData()
 └── PrintResult()

This is one of the foundations of good programming.

3. Basic Method Structure

The simplest method:

static void SayHello()
{
    Console.WriteLine("Hello");
}

Break it down:

static
  ↓
void
  ↓
SayHello
  ↓
()
  ↓
{
    code
}

Each part has a meaning.

4. Method Syntax

General structure:

accessModifier static returnType MethodName(parameters)
{
    // method body
}

For example:

public static int Add(int a, int b)
{
    return a + b;
}

Breakdown:

public
   ↓
access modifier

static
   ↓
static modifier

int
   ↓
return type

Add
   ↓
method name

(int a, int b)
   ↓
parameters

return a + b;
   ↓
method body

We will study each part carefully.

5. Method Name

Example:

static void CalculateTotal()
{
}

Here:

CalculateTotal

is the method name.

C# convention is generally PascalCase for method names:

CalculateTotal()
PrintResult()
GetUserName()
CalculateAverage()

Avoid:

calculatetotal()
calculate_total()
calculateTotal()

The compiler allows many naming styles, but following C# conventions makes code easier to understand.

6. Calling a Method

Creating a method does not automatically execute it.

Example:

static void SayHello()
{
    Console.WriteLine("Hello");
}

Nothing happens just because the method exists.

You need to call it:

SayHello();

Complete example:

class Program
{
    static void Main()
    {
        SayHello();
    }

    static void SayHello()
    {
        Console.WriteLine("Hello");
    }
}

Output:

Hello
7. Method Declaration vs Method Call

This distinction is important.

Declaration
static void SayHello()
{
    Console.WriteLine("Hello");
}

You are defining what the method does.

Call
SayHello();

You are asking the method to execute.

Think:

Declaration
    ↓
"What should this method do?"

Call
    ↓
"Do that work now."
8. void

void means:

This method does not return a value to the caller.

Example:

static void PrintName()
{
    Console.WriteLine("Hariom");
}

Calling:

PrintName();

prints something, but the method doesn't give a value back.

9. Returning a Value

Suppose we want a method to calculate a sum.

static int Add()
{
    return 10 + 20;
}

The return type is:

int

because the method returns an integer.

Call it:

int result = Add();

Console.WriteLine(result);

Output:

30
10. return

The return statement sends a value back to the caller.

static int GetNumber()
{
    return 100;
}

When we call:

int number = GetNumber();

the flow is:

GetNumber()
    ↓
return 100
    ↓
number = 100
11. Return Type Must Match

This is correct:

static int GetNumber()
{
    return 100;
}

because:

return type = int
returned value = int

This is incorrect:

static int GetNumber()
{
    return "Hello";
}

because:

int ≠ string

The compiler catches this.

12. void vs Return Value
void
static void PrintName()
{
    Console.WriteLine("Hariom");
}

Purpose:

Perform an action
int
static int GetAge()
{
    return 25;
}

Purpose:

Calculate/get something and give it back

Mental model:

void method
Input → Work → Nothing returned

returning method
Input → Work → Result returned
13. Methods with Parameters

A method can receive data from the caller.

Example:

static void Greet(string name)
{
    Console.WriteLine($"Hello {name}");
}

Call:

Greet("Hariom");

Output:

Hello Hariom

Here:

string name

is a parameter.

And:

"Hariom"

is an argument.

14. Parameter vs Argument

This terminology is important.

Method definition:

static void Greet(string name)
{
}

name is a:

Parameter

Method call:

Greet("Hariom");

"Hariom" is an:

Argument

Think:

Parameter
↓
Placeholder

Argument
↓
Actual value
15. Multiple Parameters

A method can accept multiple parameters.

static int Add(int a, int b)
{
    return a + b;
}

Call:

int result = Add(10, 20);

Console.WriteLine(result);

Output:

30

Flow:

Add(10, 20)

a = 10
b = 20

a + b
 ↓
30

return 30
16. Method With Different Data Types

Parameters can have different types.

static void PrintStudent(string name, int age, double marks)
{
    Console.WriteLine(name);
    Console.WriteLine(age);
    Console.WriteLine(marks);
}

Call:

PrintStudent("Hariom", 25, 85.5);
17. Parameter Order Matters

Consider:

static void Display(string name, int age)
{
    Console.WriteLine(name);
    Console.WriteLine(age);
}

Correct:

Display("Hariom", 25);

The arguments correspond by position:

name ← "Hariom"
age  ← 25
18. Returning Calculated Results

This is one of the most useful patterns.

static int Square(int number)
{
    return number * number;
}

Call:

int result = Square(5);

Console.WriteLine(result);

Output:

25

Flow:

Square(5)
   ↓
5 * 5
   ↓
25
   ↓
result
19. Methods Make Main() Cleaner

Without methods:

static void Main()
{
    int a = 10;
    int b = 20;

    int sum = a + b;

    Console.WriteLine(sum);

    int x = 5;
    int square = x * x;

    Console.WriteLine(square);
}

With methods:

static void Main()
{
    int sum = Add(10, 20);
    int square = Square(5);

    Console.WriteLine(sum);
    Console.WriteLine(square);
}

static int Add(int a, int b)
{
    return a + b;
}

static int Square(int number)
{
    return number * number;
}

The second version communicates intent much better.

20. Method as a Black Box

A very useful way to think about a method:

             METHOD
              ┌───────┐
Input ───────→│       │──────→ Output
              │ Logic │
              │       │
              └───────┘

For:

Add(10, 20)

think:

10 ──┐
     ├──→ Add() ──→ 30
20 ──┘

You don't need to care about the internal implementation every time you call it.

That's one of the major benefits of abstraction.

21. Method With Conditional Logic

Methods can contain any normal C# logic.

static bool IsEven(int number)
{
    if (number % 2 == 0)
    {
        return true;
    }

    return false;
}

Call:

bool result = IsEven(10);

Console.WriteLine(result);

Output:

True
22. Simplifying the Same Method

The previous method can be simplified:

static bool IsEven(int number)
{
    return number % 2 == 0;
}

This works because:

number % 2 == 0

already produces a bool.

23. Early return

A method can return before reaching the end.

Example:

static string GetGrade(int marks)
{
    if (marks >= 90)
    {
        return "A";
    }

    if (marks >= 75)
    {
        return "B";
    }

    return "C";
}

Call:

Console.WriteLine(GetGrade(85));

Output:

B

Flow:

marks = 85

85 >= 90?
No

85 >= 75?
Yes

return "B"

Once return executes, the method finishes.

24. return Stops Method Execution

Example:

static void Test()
{
    Console.WriteLine("A");

    return;

    Console.WriteLine("B");
}

Output:

A

The code after return is unreachable.

25. Methods Can Call Other Methods

Example:

static int Square(int number)
{
    return number * number;
}

static int Calculate(int number)
{
    return Square(number) + 10;
}

Call:

Console.WriteLine(Calculate(5));

Flow:

Calculate(5)
    ↓
Square(5)
    ↓
25
    ↓
25 + 10
    ↓
35

Output:

35

This allows us to build programs from smaller pieces.

26. Method Signature

Now we reach an important concept.

A method's signature is used by the compiler to distinguish methods.

For normal C# method overloading, the signature includes:

Method name
Number of parameters
Parameter types
Parameter modifiers such as ref, in, and out

Example:

Add(int, int)

and:

Add(double, double)

represent different signatures.

27. What Is Not Part of the Signature?

The return type alone does not distinguish overloaded methods.

This is invalid:

static int GetValue()
{
    return 10;
}

static double GetValue()
{
    return 10.5;
}

Why?

Both have effectively:

GetValue()

as their parameter list.

Changing only the return type is not enough to overload a method.

28. Method Overloading Preview

You can have:

static int Add(int a, int b)
{
    return a + b;
}

static int Add(int a, int b, int c)
{
    return a + b + c;
}

Now:

Add(10, 20);

selects the two-parameter method.

Add(10, 20, 30);

selects the three-parameter method.

We will study overloading separately in depth.

29. Static Methods

So far we've used:

static

Example:

static int Add(int a, int b)
{
    return a + b;
}

A static method belongs to the type itself, rather than to an individual object instance.

Therefore, inside Program:

static void Main()
{
    int result = Add(10, 20);
}

can call another static method directly.

Later, when we reach OOP, we will go much deeper into:

static
vs
instance

For now, remember:

static method
→ associated with the type
→ does not require an object instance to call it
30. Local Variables Inside Methods

Consider:

static int Add(int a, int b)
{
    int result = a + b;

    return result;
}

result is a local variable.

It exists only within the method's scope.

You cannot do:

static void Main()
{
    Console.WriteLine(result);
}

because result belongs to Add().

31. Local Scope

Example:

static void Test()
{
    int number = 10;

    Console.WriteLine(number);
}

This is valid.

But:

static void Main()
{
    Test();

    Console.WriteLine(number);
}

is invalid because number is local to Test().

Mental model:

Test()
┌─────────────────────┐
│ int number = 10;    │
│                     │
│ number is visible   │
│ here                 │
└─────────────────────┘

Main()
┌─────────────────────┐
│ number is not       │
│ visible here        │
└─────────────────────┘

We'll study local scope vs block scope more deeply as part of this module.

32. Parameters Are Local to the Method

Consider:

static int Add(int a, int b)
{
    return a + b;
}

a and b belong to the method invocation.

They aren't globally available.

You cannot access:

Console.WriteLine(a);

from Main().

33. Methods and Data Flow

Consider:

static int Multiply(int a, int b)
{
    int result = a * b;

    return result;
}

Call:

int answer = Multiply(5, 4);

Data flow:

Caller
  │
  │ 5, 4
  ↓
Multiply()
  │
  │ a = 5
  │ b = 4
  │
  │ result = 20
  ↓
return 20
  │
  ↓
answer = 20

This is the fundamental idea behind parameter passing and return values.

34. A Good Method Should Have a Clear Responsibility

Consider:

static void ProcessStudent()
{
    // read name
    // read age
    // validate age
    // calculate marks
    // save to database
    // print report
    // send email
}

This method is doing too many unrelated things.

A better design eventually becomes:

ReadStudent()
ValidateStudent()
CalculateMarks()
SaveStudent()
PrintReport()
SendEmail()

This connects directly to the Single Responsibility Principle (SRP) that we'll study later.

For now:

A method should ideally have one clear job.

35. Methods Should Be Reusable

Bad:

static void Main()
{
    int a = 10;
    int b = 20;

    Console.WriteLine(a + b);

    int x = 30;
    int y = 40;

    Console.WriteLine(x + y);
}

Better:

static int Add(int a, int b)
{
    return a + b;
}

Then:

Console.WriteLine(Add(10, 20));
Console.WriteLine(Add(30, 40));

One method handles many inputs.

36. Method Naming

Good:

CalculateTotal()
GetUserName()
IsEven()
FindMaximum()
PrintReport()
ValidateEmail()

Method names should normally describe an action or operation.

Avoid vague names:

DoStuff()
Process()
Thing()
Method1()
Test()

unless their meaning is genuinely clear from context.

37. Complete Example
class Program
{
    static void Main()
    {
        int number = 10;

        int square = Square(number);

        Console.WriteLine($"Square = {square}");

        bool even = IsEven(number);

        Console.WriteLine($"Even = {even}");
    }

    static int Square(int number)
    {
        return number * number;
    }

    static bool IsEven(int number)
    {
        return number % 2 == 0;
    }
}

Output:

Square = 100
Even = True

Notice how Main() describes the high-level flow:

Get number
   ↓
Calculate square
   ↓
Print square
   ↓
Check even
   ↓
Print result

The detailed logic lives inside separate methods.

38. Method Design Formula

When creating a method, ask:

1. What task does it perform?
        ↓
2. What input does it need?
        ↓
3. What output should it produce?
        ↓
4. What should its name be?

Example:

"I need to calculate the area of a rectangle."

Task

Calculate area.

Input
length
width
Output
area
Method
static double CalculateArea(double length, double width)
{
    return length * width;
}
39. void or Return Value?

Ask:

Does the caller need a result from this operation?

If no, void may be appropriate:

static void PrintMessage(string message)
{
    Console.WriteLine(message);
}

If yes, return the result:

static int Add(int a, int b)
{
    return a + b;
}

Think:

PrintMessage()
→ performs an action

Add()
→ produces a value

41. Common Mistakes
Mistake 1 — Forgetting to Call the Method

Defining:

static void SayHello()
{
    Console.WriteLine("Hello");
}

doesn't execute it.

You need:

SayHello();
Mistake 2 — Missing Return

This is invalid:

static int Add(int a, int b)
{
    int result = a + b;
}

The method promises an int but doesn't return one.

Correct:

static int Add(int a, int b)
{
    int result = a + b;

    return result;
}
Mistake 3 — Returning the Wrong Type
static int GetName()
{
    return "Hariom";
}

Invalid because:

int ≠ string
Mistake 4 — Trying to Use Local Variables Outside Their Scope
static void Test()
{
    int number = 10;
}

Then:

Console.WriteLine(number);

is invalid outside Test().

Mistake 5 — Trying to Overload Only by Return Type

Invalid:

static int GetValue()
{
    return 10;
}

static string GetValue()
{
    return "Hello";
}

Return type alone cannot distinguish overloads.
