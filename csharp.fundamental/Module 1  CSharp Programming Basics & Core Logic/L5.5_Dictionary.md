Lesson 29 — C# Dictionary<TKey, TValue>

Part: 5 — Collections & Errors
Topic: Dictionary<TKey, TValue>
Prerequisite: List<T>

1. Why Do We Need a Dictionary?

With a List<T>, you normally find an item using its index.

List<string> students = new List<string>
{
    "Hariom",
    "Rahul",
    "Aman"
};

Console.WriteLine(students[1]);

Output:

Rahul

The problem is that the index:

1

doesn't tell us anything meaningful about the student.

What if we want to store:

Student ID → Student Name

For example:

101 → Hariom
102 → Rahul
103 → Aman

An index-based list isn't the natural model for this.

A Dictionary<TKey, TValue> is designed exactly for this type of relationship.

2. What Is Dictionary<TKey, TValue>?

A dictionary stores data as key-value pairs.

Key → Value

Example:

101 → Hariom
102 → Rahul
103 → Aman

In C#:

Dictionary<int, string> students = new Dictionary<int, string>();

Here:

TKey   = int
TValue = string

So:

Dictionary<int, string>
        ↓       ↓
       key    value
3. Generic Structure

The general syntax is:

Dictionary<TKey, TValue>

Examples:

Dictionary<int, string>
Dictionary<string, int>
Dictionary<string, double>
Dictionary<int, bool>

You decide:

What type is the key?
What type is the value?
4. Simple Example
Dictionary<int, string> students = new Dictionary<int, string>();

students.Add(101, "Hariom");
students.Add(102, "Rahul");
students.Add(103, "Aman");

Conceptually:

students
   ↓
┌───────────────┐
│ 101 → Hariom  │
│ 102 → Rahul   │
│ 103 → Aman    │
└───────────────┘

Now we can find a student using the key:

Console.WriteLine(students[101]);

Output:

Hariom
5. Key and Value

Every dictionary entry contains two parts:

Key
 ↓
Value

For:

students.Add(101, "Hariom");

we have:

Key   = 101
Value = "Hariom"

Another:

students.Add(102, "Rahul");

means:

Key   = 102
Value = "Rahul"
6. Keys Must Be Unique

This is one of the most important rules.

Consider:

Dictionary<int, string> students = new Dictionary<int, string>();

students.Add(101, "Hariom");
students.Add(102, "Rahul");

Valid.

But:

students.Add(101, "Aman");

is invalid because key 101 already exists.

C# throws:

ArgumentException

The important rule is:

A dictionary cannot contain duplicate keys.

7. Values Can Be Duplicated

Keys must be unique.

Values do not have to be unique.

This is valid:

Dictionary<int, string> students = new Dictionary<int, string>();

students.Add(101, "Hariom");
students.Add(102, "Hariom");
students.Add(103, "Rahul");

Conceptually:

101 → Hariom
102 → Hariom
103 → Rahul

Two different keys can have the same value.

8. Creating a Dictionary With Initial Values

You can use a collection initializer:

Dictionary<int, string> students = new Dictionary<int, string>
{
    { 101, "Hariom" },
    { 102, "Rahul" },
    { 103, "Aman" }
};

Modern C# also supports:

Dictionary<int, string> students = new()
{
    { 101, "Hariom" },
    { 102, "Rahul" },
    { 103, "Aman" }
};
9. Accessing a Value Using a Key

The indexer is:

dictionary[key]

Example:

Console.WriteLine(students[101]);

Output:

Hariom

Notice something important:

With a List<T>:

students[1]

means:

index = 1

With a dictionary:

students[101]

means:

key = 101

These are conceptually different.

10. Dictionary Is Not Index-Based

This is a very important mental distinction.

List
Index → Value

0 → Hariom
1 → Rahul
2 → Aman
Dictionary
Key → Value

101 → Hariom
205 → Rahul
999 → Aman

The keys don't have to be sequential.

You can have:

dictionary.Add(5000, "Hariom");
dictionary.Add(17, "Rahul");
dictionary.Add(900, "Aman");

There is no requirement for:

0, 1, 2, 3...
11. Updating a Value

The indexer can also update an existing value.

Dictionary<int, string> students = new()
{
    { 101, "Hariom" },
    { 102, "Rahul" }
};

Now:

students[101] = "Aman";

Before:

101 → Hariom
102 → Rahul

After:

101 → Aman
102 → Rahul
12. Important Difference: Add() vs Indexer

This is one of the most important practical details.

Add()
students.Add(101, "Hariom");

If 101 already exists:

Exception
Indexer
students[101] = "Aman";

If 101 exists:

Value is updated

If 101 doesn't exist:

A new key-value pair is added

So:

Add()
 ↓
must be a new key

dictionary[key] = value
 ↓
add OR update
13. Example of Indexer Adding a New Key

Start:

Dictionary<int, string> students = new();

Then:

students[101] = "Hariom";

The dictionary becomes:

101 → Hariom

Even though we didn't call:

Add()

The indexer can create a new entry if the key doesn't exist.

14. ContainsKey()

Before accessing a key, you can check whether it exists.

if (students.ContainsKey(101))
{
    Console.WriteLine(students[101]);
}

ContainsKey() answers:

Does this key exist?

Example:

bool exists = students.ContainsKey(101);

Result:

true
15. Why ContainsKey() Is Useful

Suppose:

Dictionary<int, string> students = new()
{
    { 101, "Hariom" }
};

This is dangerous if the key may not exist:

Console.WriteLine(students[999]);

If 999 doesn't exist, the indexer throws:

KeyNotFoundException

Safer:

if (students.ContainsKey(999))
{
    Console.WriteLine(students[999]);
}
else
{
    Console.WriteLine("Student not found.");
}
16. TryGetValue() — Very Important

Instead of:

if (students.ContainsKey(101))
{
    string name = students[101];
}

you can use:

if (students.TryGetValue(101, out string name))
{
    Console.WriteLine(name);
}

This combines:

Check key
+
Retrieve value

into one operation.

17. Understanding TryGetValue()

Syntax:

dictionary.TryGetValue(key, out value)

It returns:

true

if the key exists.

It returns:

false

if the key doesn't exist.

Example:

if (students.TryGetValue(101, out string name))
{
    Console.WriteLine($"Student: {name}");
}
else
{
    Console.WriteLine("Student not found.");
}
18. Why TryGetValue() Is Usually Better

Compare:

if (students.ContainsKey(101))
{
    string name = students[101];
}

with:

if (students.TryGetValue(101, out string name))
{
}

The second form expresses exactly what you want:

Try to get this value.
If successful → use it.
Otherwise → handle absence.

It also avoids performing a separate lookup just to check before retrieving.

19. Remove()

Remove an entry using its key:

students.Remove(101);

If key 101 exists:

101 → Hariom

is removed.

If it doesn't exist, the operation simply reports that nothing was removed.

You can capture the result:

bool removed = students.Remove(101);

Then:

true

means an entry was removed.

false

means the key wasn't present.

20. Count

Like List<T>, dictionaries have:

students.Count

Example:

Dictionary<int, string> students = new()
{
    { 101, "Hariom" },
    { 102, "Rahul" },
    { 103, "Aman" }
};

Console.WriteLine(students.Count);

Output:

3

So:

List<T>
    → Count

Dictionary<TKey,TValue>
    → Count
21. Keys

You can access all keys:

foreach (int key in students.Keys)
{
    Console.WriteLine(key);
}

Output might be:

101
102
103

Conceptually:

Dictionary
    ↓
Keys
    ↓
101, 102, 103
22. Values

You can access all values:

foreach (string value in students.Values)
{
    Console.WriteLine(value);
}

Output:

Hariom
Rahul
Aman

So:

Keys
 ↓
all keys

Values
 ↓
all values
23. Iterating a Dictionary

The most useful way is:

foreach (KeyValuePair<int, string> student in students)
{
    Console.WriteLine($"{student.Key} → {student.Value}");
}

Output:

101 → Hariom
102 → Rahul
103 → Aman

Each element is a:

KeyValuePair<TKey, TValue>
24. var With Dictionary Iteration

You can make the loop shorter:

foreach (var student in students)
{
    Console.WriteLine($"{student.Key} → {student.Value}");
}

Here:

student.Key
    ↓
key

student.Value
    ↓
value

var does not mean the variable has no type.

The compiler still knows its actual type.

25. Dictionary Ordering

Don't think of a dictionary as:

position 0
position 1
position 2

That's not its purpose.

The fundamental model is:

Key → Value

If you need ordering, use appropriate APIs/data structures and don't design your program around accidental enumeration order.

The important distinction is:

A dictionary is primarily for key-based lookup, not positional access.

26. Dictionary With String Keys

Very common:

Dictionary<string, int> ages = new()
{
    { "Hariom", 21 },
    { "Rahul", 22 },
    { "Aman", 20 }
};

Access:

Console.WriteLine(ages["Hariom"]);

Output:

21

Here:

Key   = "Hariom"
Value = 21
27. Dictionary With Object Values

You can store objects as values.

class Student
{
    public string Name { get; set; }
    public int Age { get; set; }
}

Then:

Dictionary<int, Student> students = new();

Add:

students.Add(
    101,
    new Student
    {
        Name = "Hariom",
        Age = 21
    }
);

Now:

101
 ↓
Student object
 ↓
Name = Hariom
Age  = 21

This pattern is very common in real applications.

28. Dictionary With Object Keys

Keys can also be objects.

For example:

Dictionary<Student, string> studentCourses = new();

But this introduces an important concept:

How does the dictionary determine
whether two keys are the same?

That depends on equality and hashing.

For custom reference types, understanding:

Equals()
GetHashCode()

becomes important.

We'll go deeper into this when discussing collections and object equality.

For now, remember:

Dictionary keys rely on equality and hashing to identify matching keys.

29. Why Dictionary Is Fast for Lookup

The main reason to use a dictionary is efficient key-based lookup.

Conceptually:

Key
 ↓
hashing
 ↓
location/bucket
 ↓
find matching key
 ↓
value

This is fundamentally different from searching through a list one element at a time.

For example, with a list:

Find student ID 999
 ↓
check item 1
 ↓
check item 2
 ↓
check item 3
 ↓
...

A dictionary is designed to use the key to locate the relevant area efficiently.

For typical operations, dictionary lookup is approximately O(1) on average, although worst-case behavior can differ.

30. Dictionary vs List

Suppose you have:

101 → Hariom
102 → Rahul
103 → Aman
Using List

You might have:

List<Student> students;

and search:

Find Student where Id == 102

That generally requires searching through elements.

Using Dictionary
Dictionary<int, Student> students;

Then:

students[102]

directly expresses:

Give me the student associated with key 102.

This is one of the most important reasons dictionaries exist.

31. When Should You Use List<T>?

Use a list when the main concept is:

A sequence/collection of items

Example:

Students
Products
Tasks
Orders

and you primarily care about:

position
iteration
sequence
32. When Should You Use Dictionary<TKey,TValue>?

Use a dictionary when the main concept is:

Key → Value mapping

Examples:

Student ID → Student
Username → User
Country Code → Country Name
Product ID → Product
Word → Meaning

Mental model:

List
 ↓
"I have many items."

Dictionary
 ↓
"I have values identified by keys."
33. Dictionary vs Array

Consider:

string[] countries = new string[250];

This gives you positional access:

countries[0]
countries[1]
countries[2]

But if you want:

IN → India
US → United States
JP → Japan

a dictionary is more natural:

Dictionary<string, string> countries = new()
{
    { "IN", "India" },
    { "US", "United States" },
    { "JP", "Japan" }
};

Then:

countries["IN"]

gives:

India
34. Clearing a Dictionary

Remove everything:

students.Clear();

After:

Count = 0

Just like List<T>:

Clear()
 ↓
remove all entries
35. Checking for a Value

You can use:

students.ContainsValue("Hariom");

This answers:

Does any entry contain this value?

Example:

bool exists = students.ContainsValue("Hariom");

However, remember:

ContainsKey()
 ↓
key lookup

ContainsValue()
 ↓
value search

A dictionary is optimized primarily around its keys.

36. ContainsKey() vs ContainsValue()
Method	Searches
ContainsKey()	Key
ContainsValue()	Value

Example:

students.ContainsKey(101);

means:

Does key 101 exist?

While:

students.ContainsValue("Hariom");

means:

Does any entry have value "Hariom"?
37. A Common Mistake

Don't do this:

if (students.ContainsKey(101))
{
    students.Add(101, "Aman");
}

Why?

If key 101 already exists, Add() will throw an exception.

If your intention is to update:

students[101] = "Aman";

is appropriate.

If your intention is:

Add only if absent

then use logic such as:

if (!students.ContainsKey(101))
{
    students.Add(101, "Aman");
}

Or choose an API/pattern appropriate to your exact requirement.

38. Another Common Mistake

Don't assume this is safe:

string name = students[999];

If key 999 doesn't exist:

KeyNotFoundException

Use:

if (students.TryGetValue(999, out string name))
{
    Console.WriteLine(name);
}

when absence is expected.

39. Dictionary With Nullable Values

Consider:

Dictionary<int, string?> students = new();

Now a key can map to a nullable string:

students[101] = null;

This is different from the key being absent.

You have two possible states:

Key absent
    ↓
101 doesn't exist

Key present + null value
    ↓
101 exists
101 → null

This distinction can matter in application design.

40. Dictionary With Duplicate Values

This is completely valid:

Dictionary<int, string> data = new()
{
    { 1, "Apple" },
    { 2, "Apple" },
    { 3, "Apple" }
};

Keys:

1
2
3

are unique.

Values:

Apple
Apple
Apple

can repeat.

41. Complete Example
using System;
using System.Collections.Generic;

class Program
{
    static void Main()
    {
        Dictionary<int, string> students = new()
        {
            { 101, "Hariom" },
            { 102, "Rahul" },
            { 103, "Aman" }
        };

        // Count
        Console.WriteLine($"Count: {students.Count}");

        // Lookup
        if (students.TryGetValue(101, out string name))
        {
            Console.WriteLine($"Student: {name}");
        }

        // Update
        students[102] = "Ravi";

        // Add
        students.Add(104, "Sohan");

        // Check key
        if (students.ContainsKey(103))
        {
            Console.WriteLine("Student 103 exists.");
        }

        // Iterate
        foreach (var student in students)
        {
            Console.WriteLine(
                $"{student.Key} → {student.Value}"
            );
        }

        // Remove
        students.Remove(104);

        Console.WriteLine($"Final Count: {students.Count}");
    }
}

        ↓

        ↓

        ↓

43. List<T> vs Dictionary<TKey,TValue>
Question	List<T>	Dictionary<TKey,TValue>
Stores	Values/items	Key-value pairs
Access	Index	Key
Example	list[2]	dict[101]
Duplicate items	Yes	Keys: No
Dynamic size	Yes	Yes
Main purpose	Sequence	Mapping
Lookup model	Search/index	Key-based lookup
Main type parameter	T	TKey, TValue

The simplest mental distinction:

List:
"What is at position 5?"

Dictionary:
"What value belongs to key 101?"
44. Key Takeaways
1. Dictionary<TKey, TValue> stores key-value pairs.

2. TKey represents the key type.

3. TValue represents the value type.

4. Keys must be unique.

5. Values can be duplicated.

6. dictionary[key] retrieves a value.

7. dictionary[key] = value can add or update.

8. Add() throws if the key already exists.

9. ContainsKey() checks whether a key exists.

10. TryGetValue() safely retrieves a value.

11. Remove() removes using the key.

12. Keys gives the collection of keys.

13. Values gives the collection of values.

14. Count gives the number of entries.

15. Dictionary is designed primarily for key-based lookup.

16. Dictionary is not a positional collection like an array/list.

17. Dictionary lookup is typically O(1) on average.

18. Dictionary keys depend on equality and hashing.

19. Dictionary and List solve different problems.
