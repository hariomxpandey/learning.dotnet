Constructors in C#

Module: 1 — C# Programming Basics & Core Logic
Section: 1.4 Core Object-Oriented Programming
Prerequisite: Classes, Objects, Properties, Encapsulation

1. What Is a Constructor?

A constructor is a special member of a class that runs automatically when an object is created.

Example:

class Student
{
    public Student()
    {
        Console.WriteLine("Constructor called");
    }
}

When we create an object:

Student student = new Student();

C# automatically calls:

Student()

Output:

Constructor called

The important idea:

new Student()
      ↓
Constructor executes
      ↓
Object is initialized
2. Why Do We Need Constructors?

Consider:

class Student
{
    public string Name { get; set; }
    public int Age { get; set; }
}

We can create:

Student student = new Student();

But initially, the object may not contain the meaningful information we require.

We could do:

student.Name = "Hariom";
student.Age = 22;

But there is a gap:

Object created
     ↓
Object temporarily incomplete
     ↓
Properties assigned later

A constructor lets us initialize the object as it is created:

Student student = new Student("Hariom", 22);

Now:

new Student(...)
      ↓
constructor
      ↓
valid initial state
      ↓
object
3. Constructor Syntax

Basic syntax:

class Student
{
    public Student()
    {
        // initialization
    }
}

Notice something important.

A constructor:

has the same name as the class
has no return type
executes when an object is created

Correct:

public Student()
{
}

Incorrect:

public void Student()
{
}

The second one is a method, not a constructor.

4. Constructor vs Method

Compare:

public Student()
{
}

and:

public void Student()
{
}
Constructor
Same name as class
No return type
Runs during object creation
Method
Can have any valid name
Has a return type or void
Called explicitly

Example:

Student student = new Student();

Constructor runs automatically.

But:

student.Display();

requires an explicit method call.

5. Simple Constructor Example
class Student
{
    public string Name { get; set; }

    public Student()
    {
        Name = "Unknown";
    }
}

Now:

Student student = new Student();

Console.WriteLine(student.Name);

Output:

Unknown

The constructor initialized Name.

6. Constructor Runs Automatically

You don't write:

student.Student();

That would be wrong.

Instead:

Student student = new Student();

The new expression creates the object and invokes the appropriate constructor.

Think:

new
 ↓
object creation
 ↓
constructor selection
 ↓
constructor execution
 ↓
object reference returned
7. Parameterized Constructor

A constructor can receive parameters.

class Student
{
    public string Name { get; set; }
    public int Age { get; set; }

    public Student(string name, int age)
    {
        Name = name;
        Age = age;
    }
}

Now:

Student student = new Student("Hariom", 22);

The values flow like this:

"Hariom" ──→ name
22 ────────→ age
              ↓
          constructor
              ↓
          properties

Then:

Console.WriteLine(student.Name);
Console.WriteLine(student.Age);

Output:

Hariom
22
8. Why Parameterized Constructors Are Useful

Suppose a Product should always have a name and price.

Instead of:

Product product = new Product();

product.Name = "Laptop";
product.Price = 50000;

we can require those values:

Product product = new Product("Laptop", 50000);

Class:

class Product
{
    public string Name { get; }
    public double Price { get; }

    public Product(string name, double price)
    {
        Name = name;
        Price = price;
    }
}

This helps establish the object's initial state.

9. Constructor + Encapsulation

This connects directly to our previous lesson.

Consider:

class BankAccount
{
    private double balance;

    public double Balance
    {
        get
        {
            return balance;
        }
    }

    public BankAccount(double initialBalance)
    {
        if (initialBalance >= 0)
        {
            balance = initialBalance;
        }
    }
}

Now:

BankAccount account = new BankAccount(5000);

The constructor controls how the initial balance is established.

So:

private field
     ↓
constructor
     ↓
validation
     ↓
valid initial state
10. Default Constructor

A constructor with no parameters is commonly called a parameterless constructor.

Example:

class Student
{
    public Student()
    {
        Console.WriteLine("Student created");
    }
}

Usage:

Student student = new Student();
11. Compiler-Provided Parameterless Constructor

If you don't declare any instance constructor, C# generally provides an implicit parameterless constructor.

Example:

class Student
{
    public string Name { get; set; }
}

You can do:

Student student = new Student();

because the compiler provides a parameterless constructor.

But there is an important rule.

12. Important Rule — Declaring a Constructor Changes Things

Suppose:

class Student
{
    public Student(string name)
    {
    }
}

Now:

Student student = new Student();

does not work automatically.

Why?

Because once you explicitly declare an instance constructor, C# no longer automatically supplies the parameterless constructor.

You must write one if you need it:

class Student
{
    public Student()
    {
    }

    public Student(string name)
    {
    }
}

Now both work:

new Student();

and:

new Student("Hariom");
13. Multiple Constructors

A class can have multiple constructors.

Example:

class Student
{
    public string Name { get; set; }
    public int Age { get; set; }

    public Student()
    {
        Name = "Unknown";
        Age = 0;
    }

    public Student(string name, int age)
    {
        Name = name;
        Age = age;
    }
}

Now:

Student s1 = new Student();

Student s2 = new Student("Hariom", 22);

Both are valid.

This is called constructor overloading.

14. Constructor Overloading

Constructor overloading means having multiple constructors with different parameter lists.

Example:

class Product
{
    public Product()
    {
    }

    public Product(string name)
    {
    }

    public Product(string name, double price)
    {
    }
}

These are different signatures:

Product()
Product(string)
Product(string, double)

C# chooses the constructor based on the arguments supplied to new.

15. Constructor Selection

Given:

class Product
{
    public Product()
    {
        Console.WriteLine("Constructor 1");
    }

    public Product(string name)
    {
        Console.WriteLine("Constructor 2");
    }
}

If we write:

Product p1 = new Product();

C# chooses:

Product()

If:

Product p2 = new Product("Laptop");

C# chooses:

Product(string)

The compiler determines which constructor matches the arguments.

16. this Keyword in Constructors

Suppose:

class Student
{
    private string name;

    public Student(string name)
    {
        this.name = name;
    }
}

Here there are two names:

parameter → name
field     → this.name

So:

this.name = name;

means:

object's field = constructor parameter
17. Why this Is Needed

Consider:

private string name;

public Student(string name)
{
    name = name;
}

This doesn't do what we want.

Both sides refer to the parameter:

parameter name = parameter name

The field remains unchanged.

Correct:

this.name = name;

Now:

this.name
   ↓
object's field

name
   ↓
parameter
18. this Refers to Current Object

Inside an instance constructor:

this

refers to the current object.

Example:

class Student
{
    public string Name { get; set; }

    public Student(string name)
    {
        this.Name = name;
    }
}

Here:

this.Name

means:

Name property belonging to this object
19. Constructor Chaining With this

One constructor can call another constructor in the same class.

Example:

class Student
{
    public string Name { get; set; }
    public int Age { get; set; }

    public Student() : this("Unknown", 0)
    {
    }

    public Student(string name, int age)
    {
        Name = name;
        Age = age;
    }
}

Now:

Student student = new Student();

The flow is:

Student()
   ↓
this("Unknown", 0)
   ↓
Student(string, int)
   ↓
initialize properties

This is constructor chaining.

20. Why Constructor Chaining Is Useful

Without chaining:

public Student()
{
    Name = "Unknown";
    Age = 0;
}

public Student(string name, int age)
{
    Name = name;
    Age = age;
}

The initialization logic is duplicated.

With chaining:

public Student() : this("Unknown", 0)
{
}

public Student(string name, int age)
{
    Name = name;
    Age = age;
}

Only one constructor contains the actual initialization logic.

This follows the DRY principle.

21. Another Constructor Chaining Example
class Product
{
    public string Name { get; }
    public double Price { get; }

    public Product() : this("Unknown", 0)
    {
    }

    public Product(string name) : this(name, 0)
    {
    }

    public Product(string name, double price)
    {
        Name = name;
        Price = price;
    }
}

Now:

Product()
   ↓
Product(string, double)

Product(string)
   ↓
Product(string, double)

Product(string, double)
   ↓
actual initialization

This is clean constructor design.

22. Constructor Initialization Order

When an object is created, initialization follows a defined order.

At a high level for a class instance:

Object memory allocated
        ↓
Instance field initializers
        ↓
Base-class constructor processing
        ↓
Current constructor body

The exact order becomes especially important with inheritance, which we will study deeply later.

For now, remember:

Constructors are part of the object's initialization process, not ordinary methods called after creation.

23. Field Initializers + Constructor

Consider:

class Student
{
    private string name = "Unknown";

    public Student()
    {
        Console.WriteLine(name);
    }
}

When:

Student student = new Student();

the field initializer establishes the initial field value before the constructor body executes.

So the constructor sees:

name = "Unknown"
24. Property Initializers + Constructor

You can also initialize properties directly:

class Student
{
    public string Name { get; set; } = "Unknown";

    public Student()
    {
        Console.WriteLine(Name);
    }
}

The property has its initial value before the constructor body runs.

25. Constructor Can Validate Input

A constructor is a good place to reject invalid initial state.

Example:

class Product
{
    public string Name { get; }
    public double Price { get; }

    public Product(string name, double price)
    {
        if (price < 0)
        {
            throw new ArgumentException("Price cannot be negative.");
        }

        Name = name;
        Price = price;
    }
}

Now:

Product product = new Product("Laptop", 50000);

is valid.

But:

Product product = new Product("Laptop", -5000);

causes an exception.

This is stronger than silently creating an invalid object.

26. Constructor and Object Validity

This is an important OOP design principle.

Ideally:

After constructor completes
          ↓
object should be valid

Avoid designs where:

new Object()
     ↓
invalid/incomplete object
     ↓
caller must remember 5 methods
     ↓
finally valid

Prefer:

new Object(required data)
          ↓
constructor validates
          ↓
valid object
27. Constructor With private Access

A constructor can itself be private.

Example:

class Database
{
    private Database()
    {
    }
}

Then external code cannot do:

Database db = new Database();

because the constructor is private.

This pattern can be useful in specialized designs, such as controlled instance creation.

Don't use it casually; the important lesson is that constructors also have access modifiers.

28. Constructor Access Modifiers

A constructor can generally use:

public
private
protected
internal

and related accessibility combinations where applicable.

Example:

public Student()
{
}

means external accessible code can create the object, assuming the type itself is accessible.

Whereas:

private Student()
{
}

restricts construction to allowed contexts inside the type.

29. Constructor With Read-Only Properties

This is a very useful combination.

class Student
{
    public int Id { get; }
    public string Name { get; }

    public Student(int id, string name)
    {
        Id = id;
        Name = name;
    }
}

Usage:

Student student = new Student(101, "Hariom");

After construction:

Id
→ readable

Name
→ readable

direct external modification
→ not available

This gives the object a stable identity.

30. Constructor + private set

Another common pattern:

class Student
{
    public int Id { get; private set; }
    public string Name { get; private set; }

    public Student(int id, string name)
    {
        Id = id;
        Name = name;
    }
}

Now the class can modify these properties internally, but outside code cannot directly assign them.

31. Constructor vs Object Initializer

Compare:

Student student = new Student("Hariom", 22);

with:

Student student = new Student
{
    Name = "Hariom",
    Age = 22
};

The first uses a parameterized constructor.

The second:

calls a constructor
then applies object initializer assignments

Conceptually:

new Student()
      ↓
constructor
      ↓
object initializer
      ↓
final object

This distinction becomes important later.

32. Constructor + Object Initializer

Example:

class Student
{
    public string Name { get; set; }
    public int Age { get; set; }

    public Student()
    {
        Name = "Unknown";
        Age = 0;
    }
}

Then:

Student student = new Student
{
    Name = "Hariom",
    Age = 22
};

The parameterless constructor executes first.

Then the initializer assigns:

Name = "Hariom"
Age = 22
33. Constructor Parameters vs Properties

Consider:

class Student
{
    public string Name { get; }
    public int Age { get; }

    public Student(string name, int age)
    {
        Name = name;
        Age = age;
    }
}

Here:

name
→ constructor parameter

Name
→ property

age
→ constructor parameter

Age
→ property

The constructor transfers input into object state.

caller
  ↓
constructor parameters
  ↓
properties / fields
  ↓
object state
34. Constructor Overloading vs Method Overloading

Constructor overloading:

Student()
Student(string)
Student(string, int)

Method overloading:

Print()
Print(string)
Print(string, int)

The principle is similar:

same name
+
different parameter list

But constructors have special initialization behavior.

35. Constructor Signature

A constructor's signature is based on its name and parameter list for overload resolution.

Example:

Student()
Student(string)
Student(string, int)

These are distinct constructor overloads.

Changing only the return type is not relevant because constructors don't have return types.

36. Constructor Cannot Have a Return Type

This is wrong:

class Student
{
    public void Student()
    {
    }
}

That creates a method called Student.

Correct constructor:

class Student
{
    public Student()
    {
    }
}

No:

void
int
string
double

before the constructor name.

37. Constructor Cannot Be Called Like a Normal Method

Don't do:

student.Student();

A constructor is invoked through object creation:

new Student();

or:

Student student = new Student();
38. Constructor With this — Complete Example
class Employee
{
    public string Name { get; }
    public double Salary { get; }

    public Employee() : this("Unknown", 0)
    {
    }

    public Employee(string name) : this(name, 0)
    {
    }

    public Employee(string name, double salary)
    {
        Name = name;
        Salary = salary;
    }
}

Usage:

Employee e1 = new Employee();

Employee e2 = new Employee("Hariom");

Employee e3 = new Employee("Hariom", 50000);

All roads lead to:

Employee(string name, double salary)

This is constructor chaining.

39. this(...) vs this

Don't confuse these.

this

Refers to the current object:

this.Name = name;
this(...)

Calls another constructor in the same class:

public Student() : this("Unknown", 0)
{
}

So:

this
→ current object

this(...)
→ another constructor of same class
40. Constructor Execution Flow

Consider:

class Student

    public Student()
    {
        Console.WriteLine("Constructor");
    }

When:

think:

new
 ↓

41. A Good Constructor Design

A constructor should generally:

establish initial state
validate required input
maintain object invariants
avoid unnecessary work
avoid surprising side effects

Good:

public Product(string name, double price)
{
    if (price < 0)
        throw new ArgumentException("Invalid price.");

    Name = name;
    Price = price;
}

Be cautious about constructors that perform unrelated expensive operations such as large network calls or complicated external workflows.

42. Constructor Should Not Become a Huge Workflow

Avoid:

public Order()
{
    ConnectToDatabase();
    DownloadData();
    SendEmail();
    CallExternalApi();
    GenerateReport();
}

Why?

Because object creation should not unexpectedly trigger a large workflow.

Prefer:

Order order = new Order(...);

order.Process();

Separate initialization from actions when appropriate.

44. Real-World Example
class BankAccount
{
    private double balance;

    public string AccountNumber { get; }

    public double Balance
    {
        get
        {
            return balance;
        }
    }

    public BankAccount(string accountNumber, double initialBalance)
    {
        if (string.IsNullOrWhiteSpace(accountNumber))
        {
            throw new ArgumentException("Account number is required.");
        }

        if (initialBalance < 0)
        {
            throw new ArgumentException("Initial balance cannot be negative.");
        }

        AccountNumber = accountNumber;
        balance = initialBalance;
    }

    public void Deposit(double amount)
    {
        if (amount <= 0)
            return;

        balance += amount;
    }

    public bool Withdraw(double amount)
    {
        if (amount <= 0 || amount > balance)
            return false;

        balance -= amount;
        return true;
    }
}

Usage:

BankAccount account = new BankAccount("ACC101", 5000);

account.Deposit(2000);

Console.WriteLine(account.Balance);

This design has:

private balance
      ↓
protected internal state

constructor
      ↓
valid initial state

Balance
      ↓
read-only external access

Deposit()
      ↓
controlled modification

Withdraw()
      ↓
controlled modification
45. Common Constructor Mistakes
Mistake 1 — Giving constructor a return type
public void Student()
{
}

This is a method, not a constructor.

Mistake 2 — Forgetting that explicit constructors remove the implicit parameterless constructor
class Student
{
    public Student(string name)
    {
    }
}

Then:

new Student();

doesn't compile unless you explicitly provide a parameterless constructor.

Mistake 3 — Confusing this and this(...)
this.Name

means current object's member.

this(...)

means constructor chaining.

Mistake 4 — Duplicating constructor logic

Instead of:

public Student()
{
    Name = "Unknown";
    Age = 0;
}

public Student(string name, int age)
{
    Name = name;
    Age = age;
}

consider:

public Student() : this("Unknown", 0)
{
}
